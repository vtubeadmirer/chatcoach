## 0. 이 문서가 하는 일

분석 엔진이 얼마나 정확한지 재려면 '사람이 매긴 정답'이 필요하다. 그런데 사람끼리도 판단이 갈리면, AI가 틀린 건지 기준이 흐린 건지 구분할 수 없다. 이 안내서는 누가 라벨링해도 같은 결과가 나오도록 판단 기준을 고정하는 문서다.

- 이 문서는 분석의 정답 기준이다. 가상 채팅이 방송에 도움이 되는지 평가하는 기준은 별도의 '시험 평가표'에서 다룬다.
- 이 문서의 숫자(초, 분, 개수)는 모두 시작값이다. 시범 라벨링 결과를 보고 조정하며, 조정하면 버전을 올린다.
- (v0.2 추가) v0.2 에서 새로 넣은 숫자도 모두 시작값이다.
- 기준이 바뀌어도 이전 버전으로 매긴 라벨은 지우지 않고 보존한다.
- (v0.2 추가) 이 문서는 사람이 판단하는 기준만 적는다. 프로그램이 계산해 보여 주는 값(표본 추출, 화면에 보인 시간 추정, 일치도 계산)의 계산 방법은 설계 문서 [06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md)에 둔다.

## 1. 기본 원칙

1. 증거로 판단한다. '그럴 것 같다'가 아니라 영상의 어느 시각, 어떤 말, 어떤 채팅이라고 짚을 수 있어야 한다.
2. 모르면 모른다고 적는다. 억지로 등급을 고르는 것보다 '판단 불가'가 낫다. 이 값은 나중에 AI 평가에서 정답으로 쓰지 않는다.
3. AI의 판정을 보지 않고 먼저 라벨링한다. AI 결과를 먼저 보면 그쪽으로 쏠린다.
4. 원본(영상의 소리와 화면)으로 판단한다. 자동 인식 문장은 참고만 하고, 의심되면 소리를 직접 듣는다.
5. 순서를 지킨다. ① 활동 구간 → ② 저스트채팅 구간 안에서 채팅 반응 → ③ 놓친 채팅 후보.
   - (v0.2 추가 · 검토 의견 1) ④ 채팅 출처(실제/가상/판별 불가) 판정을 더한다. 2장 5단계다.
   - [제안] 출처 판정은 ③ 다음에 한다. 반응을 판정할 때 어떤 채팅이 가상인지 알면 판단이 쏠리기 때문이다.
6. '채팅에 반응했는가'로 활동 구간을 나누지 않는다. 구간은 스트리머가 무엇을 하고 있는지만으로 정한다. (잡담 화면에서 30분 동안 채팅을 안 읽었어도 그 구간은 저스트채팅이다. 그래야 '안 읽은 시간'이 평가에서 빠지지 않는다.)
7. (v0.2 추가) [제안] 판단을 쏠리게 하는 앞 결과는 가린다. 3단계에서는 2단계 반응 라벨을, 2~4단계에서는 채팅 출처를, 다시 라벨링할 때(7-3)는 처음 라벨을 보지 않는다. 원칙 3과 같은 이유다. 가린 것을 열어 봤다면 그 사실을 기록한다.

## 2. 라벨링 순서와 작업 방식

| 단계 | 하는 일 | 결과물 |
|---|---|---|
| 0 | (v0.2 추가) [제안] 영상 시각과 채팅 시각이 맞는지 확인 (아래 '시각 맞추기') | 보정 기록 |
| 1 | 방송 전체를 훑으며 활동 구간 표시 | 구간표 |
| 2 | 저스트채팅 구간 안에서, 스트리머가 채팅에 반응한 순간을 찾아 해당 채팅과 연결 (발화 쪽에서 출발) | 반응 라벨 |
| 3 | 구간 안 채팅 중 무작위 표본(시작값: 구간당 100개)을 채팅 쪽에서 출발해 판정 | 표본 라벨 |
| 4 | 반응이 연결되지 않은 채팅 중 놓친 채팅 후보 판정 | 후보 라벨 |
| 5 | (v0.2 추가 · 검토 의견 1) 채팅마다 실제/가상/판별 불가 판정 (아래 '채팅 출처 판정') | 출처 라벨 |
| 6 | (v0.2 변경: 5단계 → 6단계) 일부를 다시 라벨링해 일관성 확인 (7-3) | 일치도 |

2단계만 하면 '반응한 것'은 많이 찾지만 '반응 안 한 채팅'이 어떤 모습인지는 알 수 없다. 그래서 3단계의 무작위 표본이 필요하다. 표본은 라벨러가 고르지 않고 무작위로 뽑는다.

- (v0.2 추가) [제안] 표본은 저스트채팅 구간 안에서 경계 완충을 뺀 일반 채팅 전체에서 뽑는다. 완충 안 채팅은 처음부터 표본 수에 넣지 않으므로, 처음 뽑을 때 판정할 채팅은 정확히 100개(시작값)다. 출처는 5단계에서 따로 판정하므로 표본에서 미리 빼지 않는다.
- (v0.2 추가) [제안] 경계 완충을 뺀 일반 채팅이 표본 크기(시작값: 100개) 이하면 전부 판정한다.
- (v0.2 추가) [제안] 전부 판정하는 기준을 120개(시작값) 이하로 올린다. 110개 가운데 100개를 뽑는 것은 수고가 거의 같은데 표본 오차만 남기 때문이다. 시범에서는 100개로 두고, 시범 뒤 정한다([06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md) 2-3).
- (v0.2 추가) [제안] 한 번 뽑은 표본은 다시 뽑지 않는다. 마음에 들지 않는다는 이유로 바꾸지 않는다. 나중에 구간 경계를 고쳐도 이미 뽑힌 채팅은 그 구간 안(완충 밖)에 남아 있는 한 표본에서 빠지지 않는다. 경계를 고쳐 새로 표본에 들어온 채팅만 더 판정하므로 판정 수가 100개를 조금 넘을 수 있다. 뽑는 방법은 [06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md)에 있다.
- (v0.2 추가) [제안] 3단계는 2단계 반응 라벨을 가린 채 한다(원칙 7). 같은 채팅이 2단계와 3단계에서 다르게 판정되면 둘 다 지우지 않고 남긴다. 7-3의 불일치 사례처럼 다시 보고 최종값과 이유를 적는다.

후원 메시지와 시스템 메시지는 일반 채팅과 따로 표시하고, 아래 판정에서는 제외한다.

### 시각 맞추기 (v0.2 추가) [제안]

- 채팅 기록의 시각과 영상 파일의 시각이 어긋날 수 있다. 받은 영상의 앞부분이 잘렸거나 길이가 다를 때다. 실제로 얼마나 자주 생기는지는 확인 필요.
- 반응 라벨링 전에, 스트리머가 채팅을 소리 내어 읽거나 닉네임을 부른 순간을 3곳 이상(시작값) 찾아 채팅 시각과 비교한다.
- 차이가 거의 일정하면 가운데 값(중앙값)을 보정값으로 기록한다. 이후 모든 시각은 보정한 기준으로 본다.
- 기준이 될 순간을 3곳 찾지 못했으면 그 사실과 이유를 적는다.
- 차이가 곳마다 크게 다르면 라벨링을 멈추고 보고한다. 영상 파일이 다른 판일 수 있다.
- 보정값을 기록하는 형식은 [03-data-model](../design/03-data-model.md)에 있다.

### 채팅 출처 판정 (v0.2 추가 · 검토 의견 1)

별도 프로그램이 만든 가상 채팅이 방송에 섞여 있을 수 있다. 채팅마다 출처를 아래 세 값 중 하나로 적는다.

| 출처 | 뜻 |
|---|---|
| 실제 | 실제 시청자가 작성한 채팅 |
| 가상 | 프로그램이 생성한 가상 채팅 |
| 판별 불가 | 둘 중 어느 것인지 확정할 수 없는 채팅 |

대조 방법:

| 대조 자료 | 쓰는 법 |
|---|---|
| 가상 채팅 생성 기록 | 문구가 같거나 거의 같고 시각이 가까운 항목이 있으면 '가상' 후보 |
| 화면 문자 인식(OCR) 결과 | 방송 화면에 뜬 채팅을 읽은 결과. 생성 기록과 맞춰 보고, 채팅 기록에 없는데 화면에만 뜬 채팅을 찾는 데 쓴다 |

- [제안] '시각이 가깝다'의 시작값: 채팅 기록과 생성 기록을 맞출 때 5초 이내, 화면 문자 인식 결과와 맞출 때 30초 이내. 생성 기록의 시각이 벽시계 기준인지 영상 시각 기준인지는 확인 필요.
- [제안] 가상 채팅이 전용 계정으로 채팅창에 올라가는 방식이면 그 계정의 채팅은 '가상'이다. 가상 채팅이 어떤 경로로 방송에 들어가는지(채팅창 계정 / 화면 표시만)는 확인 필요.
- [제안] 가상 채팅 프로그램을 쓰지 않은 방송임이 확실하면 모든 채팅을 '실제'로 둔다. 누가 무엇으로 확인했는지 적는다.
- [제안] 화면에는 보이는데 채팅 기록에 없는 채팅은 '기록 밖 채팅' 목록에 따로 적고 출처를 판정한다. 삭제된 실제 채팅일 수도 있다.
- 프로그램이 자동으로 맞춘 결과는 후보일 뿐이다. 애매한 것은 사람이 보고 정한다. 자동 대조 방법은 [02-architecture](../design/02-architecture.md)에 있다.

'판별 불가'로 보내는 경우 [제안]:

- 그 시간대의 생성 기록이 없거나 빠져 있다.
- 생성 기록에 같은 문구가 시각 범위 안에 있지만, 문구가 너무 짧아(ㅋㅋ, 이모티콘만, 인사 한마디) 우연히 겹친 것인지 가릴 수 없다.
- 시각이나 문구가 일부만 맞는다.
- 화면 문자 인식 결과가 깨져 맞춰 볼 수 없다.

통계에서 다루는 법:

| 출처 | 실제 시청자 소통 통계 (반응률, 놓친 채팅 후보 비율 등) |
|---|---|
| 실제 | 포함 |
| 가상 | 제외. 제외 건수를 표시한다. [제안] 가상 채팅에 대한 반응은 '시험 평가표'용으로 따로 센다 |
| 판별 불가 | 기본으로 제외. 제외 건수를 '가상'과 나눠 표시한다 |

## 3. 활동 구간 판정 기준

한 구간에는 시작 시각, 종료 시각, 분류, 확신도, 근거 한 줄을 적는다.

- (v0.2 추가) [제안] 근거 한 줄에는 전환을 알려 준 신호의 종류(화면 / 소리 / 말 / 행동)를 함께 적는다.

| 분류 | 이럴 때 고른다 | 헷갈리기 쉬운 경우 |
|---|---|---|
| 저스트채팅 | 시청자와의 대화, 잡담, 경험·생각 공유가 활동의 중심. 게임 화면이 없거나 배경 수준 | 대화 중 잠깐 침묵해도 활동이 바뀐 게 아니면 그대로 유지 (시작값: 30초 미만). (v0.2 추가 · 검토 의견 2) 생각하거나 잠시 쉬느라 더 길게 침묵해도, 활동이 바뀐 근거가 없으면 그대로 유지 → 아래 '긴 침묵 다루기' |
| 게임 | 게임 진행이 활동의 중심. 게임 화면이 주가 되고 말이 플레이에 맞춰져 있음 | 게임 하면서 채팅과 대화해도 '게임'이다. 단, '채팅 대화 활발' 표시를 남긴다. (v0.2 추가) [제안] '활발' 기준: 10분 동안 채팅에 반응한 말이 5번 이상 (시작값) |
| 노래 | 노래를 부르는 중 (반주·가사 화면 포함) | 곡 사이 1분 미만의 멘트는 노래에 포함. 1분 넘는 잡담은 따로 저스트채팅으로 분리 |
| 기타 | 다른 활동이 확실함: 영상 시청, 자리비움, 방송 준비·대기 화면, 휴식 등 | (v0.2 변경 · 검토 의견 2) 잡담 화면에서 침묵이 길어지는 것(시작값: 2분 이상)은 재검토 신호일 뿐, 기타의 근거가 아니다. 다른 활동이 시작됐다는 근거가 있을 때만 기타로 바꾼다 |
| 판단 불가 | 화면·소리가 없거나 깨져서 알 수 없음, 신호가 서로 충돌해 결정 못 함 | '기타'는 다른 활동이라고 확신할 때, '판단 불가'는 모를 때 |

### 경계 다루기

- 활동이 바뀌는 시점은 '전환이 시작된 시각'으로 기록한다.
  - (v0.2 추가) [제안] '전환이 시작된 시각'은 새 활동의 첫 신호가 보이거나 들린 시각이다. 신호가 여럿이면 가장 이른 것으로 한다. 예고하는 말("이따 게임 할게요")은 신호가 아니다.
- 전환 앞뒤 10초(시작값)는 '경계 완충'으로 두고 채팅 반응 평가에서 뺀다.
  - (v0.2 추가) [제안] 뜻을 분명히 한다: 활동 분류가 바뀌는 경계마다 앞 10초와 뒤 10초, 합쳐 20초다. 방송 시작과 끝은 경계가 아니므로 완충을 두지 않는다.
- 구간이 30초(시작값)보다 짧으면 앞이나 뒤 구간에 합친다.
  - (v0.2 추가) [제안] 합칠 쪽: 짧은 구간과 같은 분류인 이웃이 있으면 그쪽, 없으면 앞 구간. 사람마다 다른 쪽에 합치지 않게 하려는 것이다.
- 한 구간 안에 둘 이상의 분류가 섞여 있으면 쪼갠다.

### 긴 침묵 다루기 (v0.2 추가 · 검토 의견 2)

- 긴 침묵(시작값: 2분 이상)은 '재검토 신호'다. 그 자체로 활동을 바꾸지 않는다.
- 이유: 스트리머가 생각하거나 잠시 쉬는 중이어도 저스트채팅일 수 있다. 침묵만으로 구간을 바꾸면 평가 대상 시간이 불필요하게 줄어든다.
- 신호가 보이면 그 부분을 다시 보고, 실제 활동이 바뀌었다는 근거가 있을 때만 구간을 바꾼다.
- 근거가 없으면 저스트채팅을 유지한다.
- 구간을 바꿨다면 근거 한 줄에 그 근거와 시각을 적는다. 예: "1:02:10 '물 좀 떠 올게요' 뒤 자리비움 화면".

| [제안] 근거가 될 수 있는 것 | 근거가 아닌 것 |
|---|---|
| 자리비움·대기·휴식 화면으로 바뀜 | 침묵의 길이 |
| 스트리머가 자리를 뜸(카메라가 있을 때), "잠깐 다녀올게요" 같은 말 | 채팅을 읽지 않음 (원칙 6) |
| 영상 시청 등 다른 활동이 화면에 보임 | 채팅이 적음 |

## 4. 채팅 반응 판정 기준

### 4-1. 먼저 증거를 모은다

채팅 하나와 발화 하나를 짝지어 놓고 증거를 센다.

- (v0.2 추가) [제안] (데이터 모델에 반영됨, 사용자 확정 전) 증거는 채팅–발화 짝마다 적는다. 한 채팅에 후보 발화가 여럿이면 짝마다 센다. 등급·확신도·이어짐은 짝마다가 아니라 채팅마다 하나만 정한다(4-2). 어느 후보인지 가릴 수 없어 불명확이면 후보를 전부 적는다.
- (v0.2 추가) [제안] 한 발화가 여러 채팅에 한꺼번에 답하면("여행 질문 많이 하셨는데…") 채팅마다 따로 짝을 짓고 '묶음 답변'으로 표시한다. 발화가 가리키는 묶음에 그 채팅이 들어 있다고 확인되면 '채팅을 직접 가리키는 말'(강한 증거)로 본다. 묶음에 들었는지 가릴 수 없으면 불명확.

| 증거 | 종류 | 예 |
|---|---|---|
| 강한 증거 | 닉네임을 부름 | "○○님 안녕하세요" |
| 강한 증거 | 채팅 문구를 읽거나 거의 그대로 되풀이 | 채팅 문장을 소리 내어 읽음 |
| 강한 증거 | 채팅을 직접 가리키는 말 | "방금 올라온 질문", "아까 물어보신 거" |
| 중간 증거 | 질문에 맞는 답의 형태 | 질문 직후 그 질문에 해당하는 답 |
| 중간 증거 | 채팅에만 있던 구체적 내용이 발화에 등장 | 채팅에서 처음 나온 고유한 단어·소재 |
| 중간 증거 | 채팅이 화면에 뜬 뒤 짧은 시간 안에 반응 | 시작값: 20초 이내 |
| 약한 증거 | 같은 주제 | 주제만 같고 다른 단서가 없음 |

- (v0.2 추가) [제안] '채팅이 화면에 뜬 시각'은 채팅 기록(치지직 다시보기 채팅)에 남은 시각으로 본다. 스트리머가 보는 채팅창에 뜬 시각에 가장 가까운 값이다(차이는 1초 안팎으로 추정, 확인 필요). 방송 화면의 채팅 오버레이에 뜬 시각은 쓰지 않는다. 시각이 어긋나 있으면 2장 '시각 맞추기'로 보정한 값을 쓴다.
- (v0.2 추가) [제안] 증거가 되는 소리는 스트리머 본인의 목소리뿐이다. 채팅·후원을 읽어 주는 음성(TTS), 효과음, 틀어 놓은 영상의 소리가 채팅을 읽은 것은 '읽음'이 아니다.
- (v0.2 추가) [제안] '채팅 문구를 되풀이'는 발화가 채팅보다 뒤에 올 때만 강한 증거다. 채팅이 발화보다 뒤에 있고 발화를 따라 쓴 것이면, 시청자가 스트리머 말을 옮긴 것이다. 시청자 화면은 스트리머보다 몇 초~수십 초 늦게 나오기 때문이다(치지직의 지연 시간은 확인 필요). 이런 채팅은 그 발화와 짝짓지 않는다.
- (v0.2 추가) [제안] 말 없이 웃음·끄덕임·화면 가리킴만 있는 반응은 '비언어 반응'으로 표시한다. 강한 증거는 모두 말이므로 비언어 반응만으로는 직접 반응을 주지 않는다. 등급은 증거표대로 정한다.

### 4-2. 등급 정하기

| 등급 | 조건 | 비고 |
|---|---|---|
| 직접 반응 | 강한 증거 1개 이상 | 강한 증거 없이는 직접 반응을 주지 않는다 |
| 연결 가능성 높음 | 강한 증거 없음 + 중간 증거 2개 이상 + 같은 시간대에 비슷한 다른 채팅이 없음 | |
| 관련성만 있음 | 같은 주제이지만 이 채팅이 계기라고 보기 어려움 (약한 증거만, 또는 중간 증거 1개) | 스트리머가 이미 그 주제를 이야기하던 중이었다면 여기 |
| 불명확 | 연결 후보가 있는데 어느 쪽인지 가릴 수 없음 (비슷한 채팅 여러 개, 소리가 안 들림 등) | 후보를 전부 기록한다 |

- (v0.2 추가) [제안] '같은 시간대'는 반응 발화 앞 60초(시작값)다. '비슷한 다른 채팅'은 같은 질문을 하거나 같은 소재를 꺼낸 다른 시청자의 채팅이다.
- (v0.2 추가) [제안] 같은 시청자가 한 문장을 여러 줄로 나눠 쓴 것은 '비슷한 다른 채팅'으로 세지 않는다. 한 채팅처럼 본다.

연결 후보가 아예 없으면 등급을 주지 않고 채팅 결과를 **'반응 미확인'**으로 기록한다. ('불명확'은 후보는 있는데 가리지 못하는 것, '반응 미확인'은 후보가 없는 것이다.)

- (v0.2 추가) [제안] 반대 방향도 적는다. 발화 쪽에서 출발했는데(2단계) 스트리머가 채팅에 반응한 것은 분명한데 채팅 기록에서 맞는 채팅을 찾지 못하면 '기록에 없는 채팅에 반응'으로 적는다. 발화 시각, 말한 내용, 짐작되는 이유(삭제·가림 채팅, 화면에만 뜬 채팅)를 함께 적는다. '반응 미확인'(채팅 쪽에서 후보가 없음)과 다르다.

주의: 시간이 가깝다는 사실만으로 등급을 올리지 않는다.

- (v0.2 추가 · 뜻 풀이) 시간 근접은 중간 증거 1개로만 센다. 시간이 가깝고 주제가 같은 것만으로는 '관련성만 있음'을 넘지 않는다. 규칙을 바꾼 것이 아니라 위 문장의 뜻을 풀어 쓴 것이다.

### 4-3. 읽은 순간과 대화가 이어진 순간을 따로 적는다

- 읽은(반응한) 순간: 스트리머가 처음 채팅에 반응한 시각. 영상 시각 한 점이다.
  - (v0.2 추가) [제안] 그 점은 반응 발화의 첫 음절이 시작된 시각으로 찍는다.
- (v0.2 추가) [제안] 연결 발화는 시작과 끝 시각을 함께 적는다. 끝은 그 채팅에 대한 말을 마친 지점(다음 화제로 넘어가거나 다른 채팅을 읽기 직전)이다. 7-2의 '반응 후보 발화가 끝난' 시각도 이것이다.
- 대화가 이어진 구간: 반응 이후 같은 주제가 계속된 시작~끝 시각.
  - (v0.2 추가) [제안] '같은 주제'는 같은 핵심 소재를 이어서 말하고, 그 사이에 다른 채팅을 읽거나 새 질문에 답하는 전환이 없는 것이다.

| 이어짐 라벨 | 기준 (시작값) |
|---|---|
| 이어지지 않음 | 한두 문장 답하고 다른 이야기로 넘어감 |
| 짧게 이어짐 | 같은 주제가 1분 미만 지속 |
| 확장됨 | 같은 주제가 1분 이상 지속, 또는 다른 시청자 채팅 3개 이상이 같은 주제로 이어짐 |
| 새 주제로 전환 | 이 채팅을 계기로 이전과 다른 주제가 시작됨 |

- 이어짐은 반응이 확인된 채팅(직접·연결 가능성 높음)에만 매긴다.
- 대화가 이어진 구간은 저스트채팅 구간 끝에서 자르고, 잘렸다고 표시한다.
- (v0.2 추가) [제안] 이어짐 라벨과 함께, 같은 주제로 이어진 다른 시청자 채팅 수를 적는다. 시작값(1분, 3개)이 바뀌어도 다시 분류할 수 있게 하려는 것이다.

### 4-4. 예시

1. 채팅 "여행 가면 꼭 하는 거 있어요?" → 스트리머 "○○님이 여행 가면 뭐 하냐고 물어보셨는데…" → 직접 반응 / 확실함 (닉네임 호명 + 질문 되풀이)
2. 같은 채팅 → 8초 뒤 "여행 가면 저는 무조건 맛집부터 찾아봐요" (호명·되풀이 없음, 다른 여행 채팅 없음) → 연결 가능성 높음 / 아마도 (중간 증거 2개)
3. 스트리머가 이미 여행 이야기를 길게 하던 중에 여행 관련 채팅이 여러 개 뜸 → 관련성만 있음
4. 거의 같은 질문이 서로 다른 시청자에게서 동시에 올라왔고 스트리머가 답함 → 두 채팅 모두 불명확 (후보 두 개를 기록)

(v0.2 추가) [제안] 등급과 확신도가 따로 움직이는 예, 그리고 4-1에 새로 넣은 규칙의 예:

5. 채팅 "오늘 점심 뭐 드셨어요?" → 6초 뒤 "점심은 김치찌개 먹었어요" (호명·되풀이 없음. 앞 60초에 점심 이야기도, 다른 점심 채팅도 없음) → 연결 가능성 높음 / 확실함 (중간 증거 2개, 다른 해석이 거의 없음)
6. 스트리머가 채팅 문장을 소리 내어 읽는데 뒷부분이 효과음에 묻힘. 들린 앞부분은 채팅과 같고, 비슷한 다른 채팅은 없음 → 직접 반응 / 아마도 (되풀이로 보이지만 끝까지 듣지 못함)
7. 스트리머가 "오늘 날씨 미쳤다"라고 말하고 15초 뒤 "날씨 미쳤다 ㅋㅋ" 채팅이 올라옴 → 시청자가 발화를 옮긴 것. 그 발화와 짝짓지 않는다 (4-1 되풀이 방향)

## 5. 확신도

(v0.2) 검토 의견 3에 따라 이 장의 기준은 바꾸지 않는다. 등급(연결이 어떤 성질인지)과 확신도(라벨러가 판정을 얼마나 믿는지)는 계속 따로 적는다.

확신도는 등급과 별개로, 라벨러가 그 판정을 얼마나 믿는지를 적는다.

| 확신도 | 고르는 때 | 빠른 점검 |
|---|---|---|
| 확실함 | 증거를 영상에서 직접 확인했고 다른 해석이 거의 없음 | 누가 반박하면 시각과 문장으로 답할 수 있다 |
| 아마도 | 가장 그럴듯하지만 다른 해석도 가능함 | 다른 해석을 한 문장으로 말할 수 있다 |
| 판단 불가 | 증거가 부족하거나 둘 이상이 똑같이 그럴듯해서 정할 수 없음 | 억지로 고르면 동전 던지기가 된다 |

'불명확'(등급)과 '판단 불가'(확신도)는 다르다. 불명확은 '연결이 분명하지 않다'는 판정이고, 판단 불가는 라벨러가 판정 자체를 못 내린 것이다. 비슷한 채팅이 둘이라 가릴 수 없다는 점이 분명하다면 '불명확 / 확실함'으로 적을 수 있다.

활동 구간에도 같은 방식으로 확신도를 적는다.

- (v0.2 추가) '판별 불가'(2장 채팅 출처의 값)는 확신도 '판단 불가'와 다른 칸이다.
- (v0.2 추가) [제안] 채팅 출처가 '실제'나 '가상'이면 확신도(확실함/아마도)를 함께 적는다. 어느 쪽도 정할 수 없으면 확신도를 따로 적지 않고 '판별 불가'를 고른다.

## 6. 놓친 채팅 후보 판정

'반응이 없었다'와 '검토할 가치가 있었다'는 다르다. 아래 네 조건을 모두 만족할 때만 후보로 한다.

- (v0.2 추가) [제안] 판정 대상: 3단계 표본 가운데 직접 반응·연결 가능성 높음이 아닌 채팅을 빠짐없이 본다. 표본 밖에서 눈에 띈 채팅은 '표본 밖 후보'로 따로 적고 비율 계산에는 넣지 않는다. 이유: 수천 건을 다 볼 수는 없어서, 눈에 띄는 것만 고르면 비율을 낼 수 없다.
- (v0.2 추가) 채팅 출처는 4단계 뒤에 판정하므로 후보 판정은 출처와 상관없이 한다. 통계에서 나눈다(2장 '채팅 출처 판정').

| 조건 | 기준 (시작값) |
|---|---|
| ① 구간 | 저스트채팅 구간 안이고, 경계 완충에 걸리지 않음 |
| ② 읽힐 기회 | 화면에 10초 이상 보였고, 같은 시간대에 채팅이 너무 빠르게 올라가지 않음 |
| ③ 대화 가치 | 스트리머가 답하거나 이야기를 꺼낼 거리가 있음: 질문, 경험 공유 요청, 새로운 관점, 소재가 될 이야기. 단순 인사·ㅋㅋ·반복 구호는 해당 없음 |
| ④ 반응 증거 없음 | 앞뒤 2분 안에서 같은 내용을 스트리머가 이미 다루거나 답하지 않았음 |

(v0.2 추가) [제안] ② 를 재는 방법. 스트리머의 채팅창 크기는 영상으로 알 수 없으므로 아래 근사를 쓴다. 두 값은 프로그램이 계산해 보여 주고, 라벨러는 확인만 한다.

| 값 | 정의 (시작값) |
|---|---|
| 화면에 보인 시간 | 그 채팅 뒤로 채팅 15줄이 더 올라올 때까지 걸린 시간 (15줄은 확인 필요) |
| 너무 빠름 | 그 채팅 직전 10초 동안 채팅이 20개 이상 |

점검 질문: 스트리머가 이걸 읽고 답했다면, 대화가 한 번 이상 더 이어졌을 것 같은가?

후보가 아닌 경우에는 사유 코드를 적는다.

| 코드 | 뜻 |
|---|---|
| A | 구간 밖 (경계 완충 포함) |
| B | 기회 부족 (너무 짧게 보였거나 너무 빨랐음) |
| C | 대화 가치 낮음 |
| D | 이미 다룸 |
| E | 반복·도배 채팅. (v0.2 추가) [제안] 같은 내용의 반복(한 사람이 같은 문구를 여러 번, 여러 시청자가 같은 구호)에만 쓴다. 이모티콘만·ㅋㅋ만·인사 한마디는 C |
| F | 후원·시스템 메시지 |
| G | 판단 불가 |

이 판단은 사람마다 갈릴 수 있으므로 확신도를 반드시 함께 적고, 7-3의 일관성 확인에 포함한다. 후보는 '놓쳤다'는 결론이 아니라 '다시 볼 만하다'는 표시일 뿐이다.

## 7. 검증 기록

### 7-1. 라벨 한 건에 적을 것

| 항목 | 내용 |
|---|---|
| 라벨 ID와 종류 | 활동 구간 / 채팅 반응 / 이어짐 / 놓친 채팅 후보. (v0.2 추가 · 검토 의견 1) 채팅 출처 |
| 영상 시각 | 시작·종료 (채팅은 화면에 처음 뜬 시각과 스트리머가 반응한 시각). (v0.2 추가) [제안] 두 시각은 4-1·4-3의 정의를 따른다 |
| 대상 채팅 | 닉네임(가림 처리), 본문. (v0.2 추가) [제안] 가림 방식은 [03-data-model](../design/03-data-model.md) 14장을 따른다. 시청자마다 가명(`viewer_id`, 예: `vw_zhm34oc3r6u4`)이 붙는다. 같은 방송 안에서는 같은 사람이 같은 가명이라 '다른 시청자 채팅 3개'를 셀 수 있고, 다른 방송과는 이어지지 않는다 |
| 연결 발화 | 시각과 말한 내용 (후보가 여럿이면 전부). (v0.2 추가) [제안] 시각은 시작·끝 둘 다. 말한 내용은 핵심 구절만 30자 안팎. 말한 내용에 든 호명 닉네임을 가명으로 바꿀지는 시범에서 정한다(확인 필요) |
| 증거 체크 | 강한·중간·약한 증거를 각각 무엇으로 봤는지. (v0.2 추가) [제안] 비언어 반응·묶음 답변 표시. 후보 발화가 여럿이면 후보마다 따로 적는다(4-1) |
| 등급과 확신도 | 4장·5장 기준 |
| 근거 한 줄 | 시각을 포함해서 적는다. (v0.2 변경) [제안] 예: "13:42 `vw_zhm34oc3r6u4` 호명". 근거 한 줄과 메모에는 원 닉네임 대신 가명을 쓴다. 원 닉네임을 적으면 가린 라벨 파일이 다시 식별 정보를 품는다([05-security](../design/05-security.md) A-1). (v0.2 추가) [제안] 활동 구간은 전환 신호의 종류(화면 / 소리 / 말 / 행동)도 |
| 채팅 출처 | (v0.2 추가 · 검토 의견 1) 실제 / 가상 / 판별 불가, 대조 근거(생성 기록 / 화면 문자 인식 / 그 밖의 확인 방법) |
| 이어짐 실제 값 | (v0.2 추가) [제안] 이어진 구간의 시작·끝(4-3), 같은 주제로 이어진 다른 시청자 채팅 수 |
| 영상 확인 기록 | 처음 확인한 시각, 다시 확인한 시각 |
| 라벨러·일시·기준서 버전 | 누가, 언제, 어떤 버전으로 매겼는지 |

### 7-2. 영상 재확인 규칙 (시작값)

- 확인 범위: 채팅이 화면에 뜨기 10초 전부터 반응 후보 발화가 끝난 30초 뒤까지.
- 직접 반응·연결 가능성 높음은 최소 두 번 본다 (처음 판단, 그리고 해당 지점에서 다시 듣기).
- 소리는 직접 듣고, 자동 인식 문장만 보고 판정하지 않는다.
- 첫 확인과 재확인에서 판단이 바뀌었으면 처음 판단도 함께 기록한다. 어떤 경우에 헷갈리는지 알 수 있다.

### 7-3. 일관성 확인 — '사람 불일치'와 'AI 오류' 가르기

- 라벨링한 구간의 **20~30%**를 시간을 두고 (시작값: 3일 이상) 같은 사람이 다시 라벨링한다. 가능하면 두 번째 사람이 독립적으로 매긴다.
  - (v0.2 추가) [제안] 다시 라벨링할 때는 처음 라벨을 보지 않는다(원칙 7).
  - (v0.2 추가) [제안] 다시 라벨링하는 단위는 10분 시간 블록으로 한다. 블록 안에서는 구간 경계부터 다시 매긴다. 처음 구간표를 그대로 쓰면 구간 판정의 일치도를 잴 수 없다.
  - (v0.2 추가) [제안] 한 사람이 혼자 다시 매긴 결과는 '같은 사람 안의 일치도'다. 두 사람 사이 일치도보다 높게 나오기 쉬우므로 상한으로 읽는다.
  - (v0.2 추가) [제안] 분석 엔진을 만든 사람이 라벨링했다면 그 사실을 기록한다. 엔진 규칙을 알면 라벨이 그쪽으로 쏠릴 수 있다. 가능하면 엔진을 모르는 사람이 일부 블록을 독립적으로 매겨 비교한다.
- 일치율은 한 숫자로 뭉치지 않고 등급이 같은 비율과 한 단계 어긋난 비율을 나눠 센다.
  - (v0.2 추가) [제안] '한 단계'의 순서: 직접 반응 → 연결 가능성 높음 → 관련성만 있음 → 반응 미확인. 불명확은 이 순서 밖이라 '둘 다 불명확을 골랐는지'를 따로 센다. 활동 구간 분류는 순서가 없으므로 같음/다름만 센다. 계산 방법은 [06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md)에 있다.
- 불일치 사례는 모아서 기준을 고칠지 판단한다. 같은 유형이 반복되면 기준서가 흐린 것이다.
  - (v0.2 추가) [제안] '반복'의 시작값: 같은 유형의 불일치가 3건 이상이면 기준서 개정 후보로 본다. 라벨을 바꾸거나 막지 않는다. 이 숫자를 기준서 규칙으로 둘지는 시범 뒤 정한다. 그 전에는 시범 보고서가 같은 수로 경고만 띄운다. 유형을 묶는 방법은 [06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md)에 있다.

| 상황 | 해석 | 처리 |
|---|---|---|
| 사람끼리 잘 일치하는데 AI만 다름 | AI 오류일 가능성 | AI 평가에 사용 |
| 사람끼리도 자주 갈림 | 기준이나 사례가 어려움 | AI 평가에서 분리, 기준서 개정 검토 |
| 확신도 '판단 불가' | 정답 없음 | AI 평가에서 제외 |
| 확신도 '아마도' | 약한 정답 | 참고용. 엄격한 점수에는 '확실함'만 사용 |
| (v0.2 추가 · 검토 의견 1) 채팅 출처 '판별 불가' | 출처를 모름 | 실제 시청자 소통 통계에서 기본 제외, 제외 건수 표시. [제안] AI 평가에서도 기본 제외 |
| (v0.2 추가 · 검토 의견 1) 채팅 출처 '가상' | 실제 시청자 채팅이 아님 | 실제 시청자 소통 통계에서 제외, 따로 센다. [제안] AI 평가에서도 기본 제외 |
| (v0.2 추가) [제안] 시범 라벨링에서 매긴 라벨 | 기준을 고치는 데 쓴 자료 | 개발용(dev)으로 표시하고 엔진 최종 평가의 정답에는 기본으로 넣지 않는다. 기준을 고친 자료로 평가하면 점수가 부푼다. 확정된 기준으로 다시 매긴 라벨은 쓸 수 있다([06-evaluation-and-agreement](../design/06-evaluation-and-agreement.md) 9-4) |

AI와 비교하는 점수는 '확실함'이면서 사람 일치도가 높은 라벨로 먼저 낸다. '아마도'까지 포함한 점수는 따로 보고한다.

- (v0.2 추가) [제안] 점수와 함께 제외한 건수를 이유별로 표시한다: 확신도 판단 불가, 경계 완충, 후원·시스템, 출처 가상, 출처 판별 불가, 사람 불일치.

## 8. 시범 라벨링 후 확인할 것

- 사람 간(또는 본인 재라벨링) 일치율이 낮은 항목이 있는가?
- '판단 불가'와 '불명확'이 너무 많거나 너무 적지 않은가? (많으면 기준이 어렵고, 적으면 억지로 고르고 있을 수 있다.)
- 구간 길이, 시간 창, 읽힐 기회의 시작값이 실제 방송에 맞는가?
- 직접 반응 사례가 검증용으로 충분한가? (시작 목표: 검증 구간에서 30건 안팎)
- (v0.2 추가 · 검토 의견 1) 채팅 출처 '판별 불가'가 얼마나 되는가? 많으면 생성 기록이나 화면 대조 방법부터 고친다.
- (v0.2 추가 · 검토 의견 2) '긴 침묵' 재검토 신호 가운데 실제로 구간을 바꾼 것은 몇 건이고, 근거는 무엇이었나?
- (v0.2 추가) [제안] 등급과 확신도를 엇갈려 센 표에서 특정 칸에 몰리지 않는가? (예: 연결 가능성 높음이 거의 다 '아마도'면 두 축이 한 축처럼 쓰이고 있다.)
- (v0.2 추가) [제안] 3단계 표본에서 반응이 확인됐는데 2단계에서 찾지 못한 비율(2단계 누락률)은? 높으면 2단계에서 반응을 찾는 방식을 손본다.
- (v0.2 추가) [제안] 방송마다 시각 보정값과 방송 지연이 얼마나 다른가?
- (v0.2 추가) [제안] 방송 앞부분과 뒷부분에서 반응 발견 수와 일치율이 다른가? (피로·순서 효과)
- (v0.2 변경) 다음에 기준서를 고치면 v0.3으로 올리고, 개정 이유와 바뀐 항목을 기록한다.

### v0.1 → v0.2 바뀐 항목

'상태' 열: **반영** = 검토 의견이 요구한 것. **[제안]** = 사용자 결정 전. **풀이** = 규칙은 그대로, 뜻만 풀어 씀.

'시범' 열: **전** = 시범용 기준서에 넣는다. **후** = 시범 동안 적용하지 않고, 시범 결과를 보고 v0.2 확정 때 정한다. 이 열은 기본안이고 사용자가 바꿀 수 있다. [07-roadmap](../design/07-roadmap.md) 질문 7 의 기본안(검토 의견 3건 + 도구가 값을 정하거나 기록 칸을 만들려면 꼭 필요한 정의)을 따랐다. 이유: 시범 도중에 기록 칸이나 값이 바뀌면 라벨이 섞인다. 판단을 돕는 풀이·세부 기준은 시범에서 그런 사례가 나오는지 보고 정한다.

### 방법론 검토에서 이번에 넣지 않은 것

기준서가 아니라 프로그램이 맡을 것이거나, 넣으면 기존 판정 결과가 바뀌어 사용자 결정이 먼저 필요한 것이다.

| 일치도 통계 지표(κ 등), 라벨끼리 맞추는 규칙 | 프로그램 몫. 같은 문서 |
