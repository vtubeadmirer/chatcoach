## 2. asr.json 형식 (`format: chatcoach.asr`, `format_version: 1`)

03 D15 의 프로젝트 `derived\asr.json`(보호 구역, `derived/asr*`) 자리. `engine.asr.transcribe()` 가 만들고 `write_asr_json()` 이 임시 파일 + `os.replace` 로 쓴다. UTF-8, NaN·Infinity 금지(유한하지 않은 값은 `null`). 시각은 모두 **오디오 파일 기준 정수 ms**(영상 시각으로 바꾸는 것은 앱 `core/timecode` 몫).

| 키 | 타입 | 내용 |
|---|---|---|
| `format` | str | `"chatcoach.asr"` |
| `format_version` | int | `1` |
| `created_at` | str | 전사 시작 시각 (ISO 8601, 로컬 오프셋) |
| `engine` | obj | `name`(`faster-whisper`), `version`, `ctranslate2` |
| `model` | obj | `name`(요청한 이름 또는 로컬 폴더), `repo`, `revision`(허깅페이스 스냅샷), `model_bin_sha256`, `files`({파일 이름: 바이트}) |
| `settings` | obj | 실제로 쓴 `device`·`compute_type`, 요청한 `requested_device`·`requested_compute_type`, `language`(`null`=자동), `vad`, `vad_parameters`(`null`=기본값), `word_timestamps`(실제로 단어 시각이 나왔는지), `beam_size`, `initial_prompt_sha256`, `initial_prompt_chars`, `cuda_dll_dirs`(더한 DLL 폴더 수) |
| `fallback` | obj·null | GPU 실패로 cpu int8 로 내려갔을 때 `from_device`, `from_compute_type`, `error`(앞 300자). 아니면 `null` |
| `warnings` | list[str] | 결과는 나왔지만 알아야 할 것. 지금은 `word_timestamps_failed: …` 하나 (3-3) |
| `input` | obj | `file_name`(경로 아닌 이름만), `size`, `sha256`, `sample_rate`, `channels` |
| `audio` | obj | `duration_ms`, `duration_after_vad_ms`(VAD 를 거친 뒤 남은 길이. VAD 를 끄면 원 길이와 같다) |
| `language` | obj | `detected`, `probability` (언어를 고정하면 고정값·1.0) |
| `timing` | obj | `model_resolve_s`(캐시 확인·해시), `model_load_s`, `transcribe_s`(VAD+디코딩), `total_s`, `realtime_x`(= 오디오 길이 / `transcribe_s`) |
| `vram` | obj·null | `--measure-vram` 일 때만: nvidia-smi 0.5초 표본의 `baseline_mib`·`peak_mib`·`delta_mib`. 다른 프로그램 몫이 섞인 **대략값** |
| `stats` | obj | `segment_count`, `word_count`, `char_count`(공백 뺀 글자), `speech_ms`(세그먼트 길이 합), `mean_no_speech_prob`, `mean_avg_logprob` |
| `segments[]` | list | 아래 |

`segments[]` 한 개: `id`, `start_ms`, `end_ms`, `text`(앞뒤 공백 제거), `avg_logprob`, `no_speech_prob`, `compression_ratio`, `temperature`, `words[]`.
`words[]` 한 개: `start_ms`, `end_ms`, `word`(whisper 토큰 그대로, 앞 공백 포함), `prob`. `word_timestamps=False` 이면 빈 리스트.

**개인정보.** `initial_prompt`(구간 시청자 닉네임 힌트 등)는 원문을 남기지 않고 sha256·글자 수만 적는다. `text`·`word` 에는 방송 발화가 그대로 들어 있으므로 파일 전체가 보호 구역이다. 엔진 CLI 는 표준 출력에 숫자 요약만 낸다.

형식 검사: `engine.asr.validate_asr(d) -> list[str]` (필수 키, 시각이 정수이고 `0 ≤ start ≤ end`, 세그먼트 시작이 줄지 않음, 단어 필수 키).

## 3. 측정 (p<VOD-A>, 0~5분)

입력: `chatcoach-data\audio\p<VOD-A>_0-5m.wav` (16kHz 모노 16비트, 300.011초, 미디어 에이전트가 만든 파일). 언어 `ko` 고정, beam 5, float16, GPU.
결과 파일: `chatcoach-data\projects\p<VOD-A>\derived\asr.json`(turbo, 기본) · `asr.large-v3.json` · `asr.novad.large-v3-turbo.json` · `asr.novad.large-v3.json`.

### 3-1. 기본 설정 (VAD 켬, 단어 시각 켬)

| 항목 | large-v3-turbo | large-v3 |
|---|---|---|
| 오디오 길이 | 300.0 초 | 300.0 초 |
| VAD 뒤 남은 길이 | 40.1 초 (13%) | 40.1 초 |
| 모델 로드 | 4.0~4.5 초 | 7.4~7.9 초 |
| 전사 시간 (`transcribe_s`, 3회/2회) | 2.82 · 2.86 · 3.09 초 | 7.05 · 8.46 초 |
| 실시간 배수 (`realtime_x`) | **97~106 배** | 35~43 배 |
| VRAM 최대 증가 (대략) | 약 2.2~2.3 GB | 약 4.2~4.3 GB |
| 세그먼트 수 | 15 | 15 |
| 단어 수 / 글자 수 | 55 / 151 | 52 / 152 |
| 평균 no_speech_prob | 0.000 | 0.103 |
| 평균 avg_logprob | -0.323 | -0.339 |
| 폴백 | 없음 (cuda float16) | 없음 |

두 모델 문자 차이: large-v3 기준 편집 거리 23 / 152자 = **char_diff_ratio 0.151**. 어느 쪽이 맞는지는 모른다(정답 아님). **사람 손채점 필요.**

|---|---|---|

두 모델 문자 차이 0.551. turbo 의 VAD 켬·끔 사이 차이도 크다(편집 거리 144). VAD 를 끄면 배경음 구간에서 결과가 크게 흔들린다 → **기본값 VAD 켬 유지.**

### 3-3. 관찰

1. **이 표본은 말이 적다.** 5분 중 VAD 가 말로 본 것이 40초(13%), 전사 글자 151자. 방송 시작 대기 화면·배경음악 구간으로 보인다 (ffmpeg volumedetect 평균 -31.1 dB, -40 dB 2초 무음 감지 1회 — 소리는 계속 있음). 오인식 비율·닉네임 호명 인식률을 재려면 **말이 많은 10분 표본을 따로 골라야 한다** (D-03 '끝났다의 기준').
2. **turbo 의 no_speech_prob 는 늘 0.0** 으로 나왔다 (VAD 켬·끔 모두). turbo 는 이 값으로 '말 없음' 을 거를 수 없다. 거르기는 VAD 와 avg_logprob·compression_ratio 로 해야 한다.
3. **faster-whisper 1.2.1 의 단어 정렬 버그.** large-v3 + VAD 끔에서 `find_alignment` 가 IndexError 를 냈다. `transcribe()` 는 같은 장치에서 단어 시각 없이 다시 돌고 `warnings` 에 적는다. 기본 설정(VAD 켬)에서는 나지 않았다.
4. **av 19 비호환.** av 19.0.1 은 `av.open(metadata_errors=)` 를 없애 faster-whisper 1.2.1 의 오디오 읽기가 TypeError 로 실패한다. `requirements-engine.in` 에 `av<19` 를 넣었다 (잠금은 18.1.0).
5. GPU(cuda float16)가 첫 시도부터 동작했다. 시스템 CUDA 툴킷 없이 pip 휠 DLL 만으로 된다.

## 4. 1시간 처리 시간 추정 (**추정**, 5분 결과 외삽)

전사 시간은 오디오 길이보다 **VAD 뒤 말 길이**에 비례한다. 이 표본은 말 비율이 13% 라 단순 12배는 낮게 잡힌다. 두 끝을 적는다.

| 모델 | 이 표본과 같은 말 비율(13%)로 ×12 | 1시간 내내 말한다고 볼 때 (전사 초 / VAD 뒤 초 × 3600) | 모델 로드 |
|---|---|---|---|
| large-v3-turbo | 약 34~37 초 | 약 4.3~4.6 분 (2.82~3.09 / 40.1 × 3600 = 253~277 초) | +4 초 |
| large-v3 | 약 1.4~1.7 분 | 약 10.5~12.7 분 | +8 초 |

수다 방송의 실제 말 비율을 50~70% 로 보면 turbo 로 **약 2~3.5 분 / 1시간** (추정). D-04 '처리 시간이 방송 길이보다 길면 다시 본다' 조건과는 거리가 멀다. **확인 필요:** 실제 1시간 파일 한 번 측정(긴 파일에서 VRAM·속도 유지 여부).
