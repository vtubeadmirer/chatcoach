## 2. 결과 형식 — ai-result schema_version 2 초안

`schemas/ai-result.schema.json`(v1)에는 증거·확신도·후보 칸이 없다. 스키마 파일은 고치지 않고, link-v0 은 아래 v2 초안 모양으로 파일만 쓴다.
`--v1-out` 을 주면 v1 스키마에 맞는 부분(최상위 v1 키 + `reactions[]` 의 v1 7개 키)만 따로 쓴다. v1 과 바뀐 점만 적는다.

### 2-1. 최상위

| 키 | v1 | v2 초안 |
|---|---|---|
| `schema_version` | `1` | `2` |
| `x_draft` | — | 초안 표시 문자열(이 문서를 가리킴) |
| `media` | 객체 또는 null | `null` (time_axis = vod_ms) |
| `calibration` | — | `{source: default·project.json·cli, offset_ms, method, file_start_in_vod_ms, status, needs_anchor_calibration}`. offset_ms 는 timecode.Calibration 과 같은 뜻(영상 = VOD − 클립 시작 + offset) |
| `scope` | — | `{start_ms, end_ms, asr_duration_ms}` — 판정한 채팅 VOD 범위 |
| `inputs` | — | `{asr_sha256, asr_segments, identities_used}` |
| `config` | — | LinkConfig 전체(안내서 시작값 `rule` + 엔진 시작값). `engine.config_sha256` 은 이 객체의 정규화 SHA-256 |
| `stats` | — | 1장 표의 숫자들(`grade_counts`, `confidence_counts`, `evidence_present`, `elapsed_s`, `load_s` …) |
| `engine.components.other` | 자유 문자열 | `"features-v0 rules-v0.1"` |

`segments`·`continuations`·`missed_candidates`·`origins` 는 link-v0 이 내지 않아 뺀다(03 17장 '부분 결과').

### 2-2. `reactions[]` (text 채팅 하나에 한 줄)

v1 키(`chat_id`, `result`, `grade`, `reaction_time_ms`, `utterance_start_ms`, `utterance_end_ms`, `score`)는 뜻이 같다. 시각은 모두 VOD ms 정수다.
`score` = 연결한 후보의 점수(3장 가중치 합). 더한 키:

| 키 | 타입 | 뜻 |
|---|---|---|
| `chat_t_ms` | int | 채팅 VOD 시각(messages.t_ms 사본, 정렬·검토용) |
| `eligible_grades` | [grade] | rules.grade_conditions 의 조건 충족 목록(03 6-7 과 같은 뜻) |
| `confidence` | `certain`·`probably`·`undeterminable`·null | 엔진 확신도(3장 7) |
| `confidence_margin` | number·null | (1위 점수 − 2위 점수) / 1위 점수. 후보가 하나면 2위 = 0 |
| `unclear_cause` | `multiple_utterances`·`multiple_similar_chats`·null | grade 가 unclear 일 때만 |
| `no_similar_chat_nearby` | bool | ±similar_window 안에 비슷한 다른 시청자 채팅이 없음 |
| `similar_chat_ids` | [chat_id] | 그 비슷한 채팅들 |
| `streamer_already_on_topic` | bool | 채팅 앞 60초 발화가 채팅의 내용어를 이미 말함 |
| `nickname_evidence_available` | bool | false 면 닉네임 호명이 판단 불가(null) |
| `window_utterances` | int | 시간 창 안 발화 수(후보가 되지 못한 것 포함) |
| `linked_candidate` | int·null | `candidates[]` 안에서 연결한 후보 위치 |
| `candidates[]` | | 시간 창 말고 다른 증거가 하나 이상인 발화만. 각 원소: `asr_segment_id`, `utterance_start_ms`, `utterance_end_ms`, `tier`(후보 단계), `score`, `strong`·`medium`·`weak`(센 개수), `evidence`(7키 → `{present: bool·null, at_ms}`, label-event `evidenceItem` 과 같은 모양에서 `note` 만 뺌) |
| `reasons` | [str] | 규칙 계산 사유 코드(`time_only:i`, `likely_blocked:similar_chat:i`, `evidence_unknown:nickname_called:i`, `tie:likely`, `similar_chat_nearby`, `multiple_direct`, `no_candidates` …) |
| `rationale` | str | 근거 한 줄. **시각과 증거 이름만** 쓴다(본문·닉네임 없음). 예: `00:04:29.3 발화: 문구 되풀이(강)·고유 내용(중)·시간 창(중)·같은 주제(약)` |

## 3. 규칙과 시작값

### 3-1. 안내서 시작값 (guide-config v0.1, `RuleConfig`)

| 값 | v0.1 | 쓰는 곳 |
|---|---|---|
| `reaction.time_window_sec` | 20 | 후보를 모으는 창 [채팅, 채팅+20초] 과 `within_time_window` |
| `reaction.direct_min_strong` | 1 | 직접 |
| `reaction.likely_min_medium` | 2 | 높음 |
| `reaction.similar_chat_window_sec` | null(미정) | null 이라 엔진 값 20초를 쓴다(3-3) |
| `evidence_strength` | 강 3 · 중 3 · 약 1 (03 5-7) | 셈 |

`assets/guide-config.v0.1.json` 이 아직 없어 위 값을 `rules.V0_1` 에 코드로 두었다. 파일이 생기면 `RuleConfig.from_values(values)` 로 읽는다.

### 3-2. 규칙 해석 (`app/core/rules.py`, 안내서에 없는 부분)

1. **시간 근접만으로 올리지 않음.** `within_time_window` 는 같은 후보에 다른 증거가 하나라도 있을 때만 중간 증거로 센다. 다른 증거가 없는 발화는 엔진이 후보로 올리지 않는다(그래서 350짝 → 9후보).
2. **'높음' 의 '비슷한 채팅 없음'.** True 일 때만 높음. False(있음)면 높음을 막고 '불명확' 을 조건 충족에 넣는다. None(모름)이면 막기만 한다.
3. **'이미 그 주제'** 이면 높음을 막는다(4-2 비고).
4. **동점.** 강한 증거 없는 '높음' 후보가 둘 이상이면 불명확(multiple_utterances). 직접 단계 동점은 불명확으로 보지 않는다.
5. **모르는 증거(None)** 는 세지 않고 사유만 남긴다.
6. **gate**(v0.1 미사용): 세지 않고, 없으면 직접·높음을 막는다.
7. **엔진의 등급 고르기**(`link._pick_grade`, 앱은 고르지 않음): 직접 → 단, 비슷한 채팅이 있으면 닉네임 호명일 때만 직접, 아니면 불명확(예시 4: 되풀이는 어느 채팅인지 가르지 못함) → 동점·비슷한 채팅으로 높음이 막히면 불명확 → 높음 → 관련성만.
   **확신도**: 불명확 = 아마도, 직접이고 margin ≥ 0.5 = 확실함, margin ≥ 0.25 = 아마도, 그 밖 = 판단 불가. 높음·관련성만은 확실함이 되지 않는다.

### 3-3. 엔진 시작값 (`LinkConfig`, 안내서 숫자 아님)

| 값 | 시작값 | 뜻 |
|---|---|---|
| `similar_window_ms_default` | 20000 | similar_chat_window_sec 가 null 일 때 비슷한 채팅을 찾는 ±창 |
| `similar_min` | 0.5 | 비슷한 채팅: 문자 bigram Dice 하한(같은 시청자 채팅은 제외, anon 은 포함) |

### 3-4. 실데이터 첫 검토 뒤 고친 것

같은 5분을 한 번 돌려 연결된 7건을 개발자가 원문과 대조했고(저장소 밖에서만), 거짓 양성 3건이 나와 다음을 고친 뒤 다시 돌렸다. 1장 숫자는 고친 뒤 값이다.

| 거짓 양성 유형 | 고친 것 |
|---|---|
| 인사만 있는 채팅을 스트리머가 인사로 받은 것을 '문구 되풀이(강)' → 직접 | 내용어가 없는 채팅은 되풀이를 판정하지 않음 |
| 내용 없는 채팅('?' 하나)에 '답의 형태' | 내용 없는 채팅은 답의 형태를 판정하지 않음 |
| 다른 사람을 '…님이' 로 부른 발화가 흔한 인사말 겹침만으로 '직접 지칭(강)' | 직접 지칭은 Dice 가 아니라 내용어 공유·되풀이·답의 형태가 있어야 셈 |

고치기 전 분포: 직접 3 · 높음 1 · 관련성만 3 · 미확인 147. 같은 5분으로 규칙을 고치고 다시 잰 것이라 **이 숫자는 과적합된 값이다.** 다른 구간에서 다시 재야 한다.

## 4. 특징 계산 (`engine/features.py`)

| 함수 | 하는 일 |
|---|---|
| `normalize` · `compact` | 이모티콘 토큰 `{:x:}`·낱자(ㅋㅋ·ㅠㅠ)·기호 제거, 소문자, 공백 하나로 / 공백 제거 |
| `char_ngrams` · `dice` · `containment` · `similarity` · `longest_common_substring` | 문자 n-gram(기본 bigram)과 유사도 |
| `content_tokens` · `shared_content` | 거친 내용어(조사 떼기 전·후 둘 다, 불용어 제외) |
| `is_question` | '?' · 의문사(뭐·어디·언제·누구·왜·어떻게·몇 …) · 의문 전용 어미(~나요·~까요·~가요·~냐·~니 …) |
| `direct_reference_terms` | 직접 지칭 사전 |
| `answer_form` | 채팅이 질문이고, 발화가 답 표지(네·아니·저는 …)로 시작하거나 내용어를 공유. 발화가 되묻기면 아님 |
| `text_repeated` · `unique_content` · `same_topic` | 3-3 표 |
| `nickname_called` | 닉네임 목록이 없으면 None(판단 불가). '님' 앞 글자 길이 −1~+1 을 떼어 자모 편집 거리 비교. 2글자 미만 닉네임은 판정 안 함 |
| `is_low_content` · `repeat_ratio` · `similar_indices` | 반복·도배 보조 |

형태소 분석기·사전 없이 쓰는 근사라 한계가 분명하다: 조사 떼기가 명사를 자르는 경우(예: '…도' 로 끝나는 지명), 동사 활용형을 내용어로 잘못 보는 경우, ASR 이 띄어쓰기를 달리 하는 경우.

## 5. 개인정보

- 결과 json·표준 출력·이 문서에는 채팅 본문·닉네임·전사문이 없다(테스트가 합성 데이터로 검색해 확인한다).
- 닉네임 원문은 `identities.jsonl` 에서 메모리로만 읽어 호명 비교에 쓴다.
- `link-v0-review.csv` 열: chat_id, 채팅 VOD 시각, 발화 VOD 시각, 등급, 확신도, 점수, 증거 키. 본문 없음. 저장소 밖에만 둔다.
  이번 실행은 등급이 있는 채팅이 6건이라 20건이 아니라 6줄이다.

## 6. 남은 일·확인 필요

1. `python -m engine link` 하위 명령: `engine/__main__.py` 에 `link` 를 붙여 `engine.link.main(argv)` 로 넘기면 된다(엔진 담당).
2. 층: `engine/link.py` 가 `app.core.rules`·`app.core.timecode`·`app.jsonl` 을 import 한다. `engine/__init__.py` 는 "engine 은 app 을 import 하지 않는다" 고 적고 있다. 등급 규칙을 앱과 한 벌로 쓰려면 이 import 가 필요하다. 문서 문구를 'engine 은 app.core(순수)와 app.jsonl 만 import 한다' 로 바꿀지 결정이 필요하다.
3. ai-result v2: 이 문서 2장을 스키마로 옮길지, 옮긴다면 `candidates[].evidence` 를 label-event 의 `evidence` 정의와 공유할지.
4. `similar_chat_window_sec` 가 v0.1 에서 null 이다. 엔진은 20초를 쓰지만 안내서 값으로 정해야 한다.
5. 보정: 앵커 3개로 오프셋을 정한 뒤 다시 잰다(1-2 처럼 10초 어긋나면 결과가 바뀐다).
6. 정확도: 사람이 매긴 직접 반응 30건과 비교(D-03 4번)는 정답이 생긴 뒤.
7. 말 많은 10분 구간의 asr.json 이 필요하다(엔진 담당 보고의 열린 문제와 같음).
