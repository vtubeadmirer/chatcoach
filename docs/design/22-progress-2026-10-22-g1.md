## 2. 세 축 채점 결과 (합성 예문)

채점기 0.2 를 합성 맥락에 돌린 결과다. 보고를 쓰며 다시 돌려 확인했다.
합성 맥락: 주제 흐름 낱말 '떡볶이·치즈·분식'(0~300초). 전사 창 60~70초 '떡볶이·치즈·맛있다', 70~80초 '매운맛·주문·배달', 80~90초 '양념·어묵'. 앞 채팅 95초 '배달 왔다 ㅋㅋ', 98초 '안녕하세요 ㅋㅋ'. 보낸 시각은 100초.

| 예문 (합성) | 앞서 쓴 내 글 | 주제 적합성 | 대화 확장성 | 반복 여부 |
|---|---|---|---|---|
| 떡볶이에 치즈 넣으면 어떤 맛이에요? | 없음 | good (flow_hit) | good (open_question) | good (fresh) |
| 어묵 양념 매운가요? | 없음 | good (talk_hits) | good (yes_no_concrete) | good (fresh) |
| 떡볶이 맛있겠다 | 없음 | good (flow_hit) | ok (concrete) | good (fresh) |
| 그렇게 하면 되는 거예요? | 없음 | weak (no_words) | ok (yes_no) | good (fresh) |
| ㅋㅋㅋㅋ {:zz_test_01:} | 없음 | weak (no_words) | weak (reaction_only) | good (fresh) |
| 안녕하세요 | 없음 | weak (no_overlap) | weak (thin) | good (fresh) |
| 배달 왔다 ㅋㅋ | 없음 | ok (talk_one) | ok (concrete) | **weak (copy_same)** |
| 떡볶이에 치즈 넣으면 어떤 맛이에요? (110초) | 같은 글 1개 | good (flow_hit) | good (open_question) | **weak (self_same)** |
| 뭔가 이상해요 | 없음 | weak (no_overlap) | weak (thin) | good (fresh) |
| 어묵 최고! | '…!' 3개 | ok (talk_one) | ok (concrete) | ok (habit) |
| 치즈 좋다 ㅋㅋ | '…ㅋㅋ' 3개 | good (flow_hit) | ok (concrete) | **weak (habit)** |

읽는 법:
- 서술은 아무리 구체적이어도 대화 확장성이 **ok 까지**다. good 은 열린 질문, 또는 구체적인 예/아니오 질문뿐이다.
- '그렇게 하면 되는 거예요?' 는 검토 전에는 주제 good·확장 good 이었다. 기능어를 빼서 이제 weak·ok 다(4-1 의 1번).
- '뭔가 이상해요' 는 검토 전에는 열린 질문(good)이었다. 이제 서술(weak)이다(4-1 의 3번).
- 'ㅋㅋ' 로 끝내는 글이 최근 5개 가운데 3개면 weak 다. 너무 엄할 수 있다(5-2 의 4번).

검토 뒤 다시 잰 것 (수정 담당, 합성):

| 예문 (합성) | 검토 전 | 검토 뒤 |
|---|---|---|
| 그렇게 하면 되는 거예요? | 주제 good / 확장 good | 주제 weak (no_words) / 확장 ok (yes_no) |
| 그래도 재밌네요 + 전사 '그래가지고' | 주제 ok (talk_one) | 주제 weak (no_overlap) |
| 안녕하세요 + 앞 채팅 '안녕하세요 ㅋㅋ' | 반복 weak (copy_similar) | 반복 good (fresh) |
| 열린 질문을 연달아 4번 | 반복 weak (habit) | 반복 good (fresh) |
| '!' 로 끝나는 글 4번 | 반복 weak | 반복 ok (habit) |
| 전사 창 30~40초, 보낸 시각 30초 또는 120.001초 | 주제 ok (talk_one) | 주제 ok (no_context) |

스모크(`<P>` 사본, 합성 글 3개): 주제 맞는 질문 good/good/good, 이모티콘만 weak/weak/good, 앞 글 베끼기 good/good/weak. 요약은 축마다 2/0/1.

| 지금 할 수 있나 | **됨.** `<P>` 손라벨·합성으로 | 됨. 다만 품질 관문 H-5 는 사용자가 채팅마다 판정 | **안 됨.** 시범 라벨링이 끝나 세션이 모두 잠겨야 함(D-17 4) |

### 7-1. G 둘째 할 일과 끝났다의 기준

| 순서 | 할 일 | 끝났다의 기준 |
|---|---|---|
| 0 | 정리: 5-2 의 1(Claude 몫)·6·7·11·12·15, 5-3 의 2(허락 뒤), 실제 창 스모크 한 번 | 시험 통과, 문서·코드 같은 말 |

### 7-2. 시범이 끝나면

시범 세션이 모두 잠기면 G 둘째 중간이라도 **시범 해제 뒤 첫 실제 비교**를 먼저 한다. 그때 시청자 훈련 메뉴도 시범 프로젝트에서 켜진다(D-20 5).
