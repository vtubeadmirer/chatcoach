| 2 | 검토자가 다시 뽑을 때(`draw_no`+1) 앞 판의 판정을 이어받을까? | 이어받음 (판정함으로 셈) | '다시 판정' 이 목적이면 따로 규칙이 필요. 정하기 전까지 그대로 |
| 3 | 기존 v1 계열을 v2 로 옮기는 방법 | 검토자가 `draw_no` 를 올려 다시 뽑아야 함 | 그대로 (실제 v1 매니페스트 없음) |
| 4 | 이어짐 비움 경고 코드를 label-event 스키마에 넣을까? | `other` + detail | `continuation_missing` 을 코드 목록에 넣음 (03 414행도) |
| 5 | 설계 문서의 남은 v1 문구 | 그대로 | 다음 묶음 처음에 한 번에 고침 |

## 5. 사용자가 직접 해 볼 것 — 11 보고 5장과 달라진 점만

순서는 [11](11-progress-2026-10-21-c2.md) 5장과 같다. **5-0 백업을 먼저 한다.** 아래는 달라진 점만 적는다.

| 11 의 절 | 달라진 점 |
|---|---|
| 5-1 의 6 | **영상 연결을 먼저 한다.** 영상이 없으면 구간 저장·반응 저장·표본 뽑기가 모두 막힌다. 연결하면 상태 줄에 영상 범위가 보인다 |
| 5-1 | 상태 줄이 하나다. 칩(라벨러·세션 등)이 메인 창 아래 상태 줄 오른쪽에 있다 |
| 5-2 | 영상과 겹치지 않는 구간은 저장이 막히고 이유가 보인다. 일부만 걸친 구간은 '일부만 영상 안' 표시와 함께 저장된다 |
| 5-2 | 분류만 고르고 근거를 비운 구간도 모드를 바꿀 때 '저장 안 한 변경' 으로 묻는다 |
| 5-2·5-3 | 저장하는 동안 바쁨 커서와 '저장 중…' 이 잠깐 보인다 |
| 5-3 | 대상 채팅의 확인 범위(−10초 ~ +30초)가 영상 밖이면 저장 단추가 꺼지고 이유가 보인다 |
| 5-3 | 직접·높음인데 이어짐을 비우면 경고 줄이 보인다. 저장은 된다 |
| 5-3 | 편집기 배치가 바뀌었다. 등급 단추가 2칸 격자, 발화 시작·끝이 두 줄 |
| 5-3 의 2 | 이미 라벨이 있는 채팅을 열면 새 라벨이 아니라 그 라벨을 고친다 |
| 5-4 의 1 | **영상 밖 표본이 나오지 않는다.** 표본 줄에 `sha256-tau-v2` 와 '영상 밖 N' 이 보인다. 11 의 '알려진 문제'(파일 0초에서 반복)는 없어졌다 |
| 5-4 | **② 에서 매긴 채팅이 표본에 나오면** '판정함' 으로 보인다. 빠른 단추(`Ctrl+5`·판단 불가)는 꺼지고, `M` 으로 그 라벨이 열린다. 저장해도 진행률이 오르지 않는다(이미 셈) |
| 5-5 의 2 | 이어짐을 비운 직접·높음 반응이 있으면 `manifest.json` 의 `warnings` 에 그 건수 1줄이 있다 |
| 자동 점검 | 같은 명령. **26줄**이 모두 PASS, 종료 코드 0 이면 통과. 노트북 크기를 보려면 `--window-size 1366x768` 을 붙인다 |

해 보고 알려 줄 것 (11 의 5-6 에 더함):

| # | 무엇 |
|---|---|
| 1 | 바쁨 커서가 눈에 보이는지, 거슬리는지 |
| 2 | 노트북 화면에서 상태 줄 왼쪽 문장이 잘려 불편한지 |
| 3 | 영상 없이는 아무것도 저장 못 하는 것이 괜찮은지 (4-3 의 1번) |
| 4 | ③ 에서 ② 라벨을 고치는 흐름이 헷갈리지 않는지 |
