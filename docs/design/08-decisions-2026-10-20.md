## D-01. 제품의 정의

**배경.** 지금까지 만든 StreamLabeler 는 "사람이 다시보기를 보며 스트리머가 어느 채팅에 반응했는지 표시하는 라벨링 도구" 로 설계됐다. 사용자의 원래 기획은 채팅과 스트리머 발화를 분석해 스트리머의 채팅 읽기 훈련과 시청자의 채팅 쓰기 훈련을 하는 프로그램이다.

**결정.** 기획 초안을 제품의 정의로 삼는다. StreamLabeler 의 자산은 버리지 않고 제품 안에서 네 자리를 맡는다.

| 자리 | 하는 일 |
|---|---|
| 정답지 | 사람이 판정한 반응 라벨을 만든다 (기획 초안 11장 질문 6 의 답) |
| 채점기 | 자동 분석 엔진의 판정을 정답과 비교해 점수를 낸다 |
| 화면 부품 | 작업대(영상·타임라인·채팅 패널)를 분석 모드·훈련 모드가 같이 쓴다 |
| 데이터 바닥 | 채팅 수집·가명화·시간 맞추기를 모든 모드가 같이 쓴다 |

**제품의 세 모드** (기획 초안 8장)

| 모드 | 첫 버전의 모습 |
|---|---|
| 방송 분석 (8.3) | 지난 방송을 열면 사람 판정과 엔진 판정이 나란히 보이고, 주제 흐름과 방송 요약이 나온다 |
| 스트리머 훈련 (8.1) | 실제 채팅을 다시 틀고 스트리머 목소리는 끈다. 사용자가 고른 채팅을 원래 반응과 비교해 보여 준다 |
| 시청자 훈련 (8.2) | 방송의 한 시점을 고르고 채팅을 써 보면 주제 적합성·대화 확장성·반복 여부를 축별로 보여 준다 |

**하지 않는 것.** 실제 치지직 채팅창에 자동으로 글을 보내지 않는다 (기획 초안 10장).

- 스트리머에게는 채팅 읽기 코치, 시청자에게는 채팅 쓰기 코치라 두 사용자를 한 이름에 담는다.
- 짧고 한글·영문 모두 바로 읽힌다.
- 공개 릴리스가 아직 없어 지금 바꾸는 비용이 가장 작다.

## D-03. 엔진 시험판 시점

**결정.** 자동 분석 엔진의 시험판(B단계)을 데이터 바닥(A단계) 바로 뒤에 넣는다. 기간은 4~6일 상한이다.

**이유.** 제품의 핵심인 "스트리머가 무슨 말을 했나" 가 STT 에 달려 있다. STT 가 쓸 만하지 않으면 라벨링 도구 완성(약 12~15일)보다 먼저 알아야 방향을 바꿀 수 있다. 엔진이 내는 결과 모양을 보고 반응 편집기를 맞춰 만들 수 있다.

**시험판이 하는 일**
1. 영상에서 16kHz 모노 음성을 뽑는다 (ClipSlicer 의 ffmpeg 함수를 고쳐 쓴다).
2. STT 를 돌려 문장·단어 시각을 얻는다 (D-04).
3. 안내서 4-1 의 증거 7종을 자동으로 찾고 4-2 규칙으로 등급을 매긴다.
4. 사람이 손으로 매긴 직접 반응 30건과 비교해 대략의 정확도를 본다.

**끝났다의 기준.** 1시간 방송의 STT 처리 시간, 10분 표본의 오인식 비율, 30건 기준의 맞힌 비율을 측정값으로 남긴다.

**대가.** 기존 로드맵(07)의 "MVP 범위 밖은 파일도 만들지 않는다"(ADR-10)와 순서가 달라진다. 이 결정으로 ADR-10 을 고친다. 엔진의 정확한 채점은 시범 라벨링 정답이 생긴 뒤 다시 한다.

**바뀐 단계 순서**

| 단계 | 내용 | 기획 초안 | 작업일 추정 |
|---|---|---|---|
| A | 채팅 수집·시간 맞추기·활동 구간 | 9장 1단계 | 5~6 |
| **B** | **엔진 시험판** | 9장 1단계 | 4~6 |
| C | 라벨링 도구 완성 | 9장 1단계 | 12~15 |
| D | 시범 라벨링 3편, 안내서 v0.2 | 9장 1단계 | 3~4 |
| E | 방송 분석 모드 | 9장 2단계 | 8~12 |
| F | 스트리머 훈련 | 9장 3단계 | 6~9 |
| G | 시청자 훈련·스트리머 프로필 | 9장 4단계 | 8~12 |

합계 약 50~70 작업일(추정). 멈출 지점은 아직 정하지 않았다 (6장 열린 질문).

## D-04. 음성 인식(STT)

**결정.** 개발 PC 에서 로컬로 돌리는 **faster-whisper** 를 쓴다. 기본 모델은 **large-v3-turbo**, 10분 표본에서만 **large-v3** 와 비교한다.

**이유.**
- 음성이 PC 밖으로 나가지 않는다 (D-06).
- 개발 PC 에 NVIDIA GPU·CUDA 가 있어 GPU 로 돌릴 수 있다.
- 단어별 시각이 나와 "채팅 몇 초 뒤 반응" 을 잴 수 있다.
- 말 없는 구간 거르기(VAD)가 들어 있다.
- 그 구간 시청자 닉네임 목록을 힌트(initial prompt)로 넣어 닉네임 호명 인식을 보강할 수 있다.
- MIT 라이선스.

**배치.** 앱 zip 에 넣지 않는다. 모델이 수 GB 이기 때문이다. 개발 PC 의 엔진 도구로만 쓰고, 결과는 프로젝트 `derived\asr.json`(보호 구역)에 모델 이름·해시와 함께 저장한다. 기존 ADR-18 과 같은 방향이다.

**측정할 것 (B단계).** 1시간 처리 시간(GPU), 10분 표본 오인식 비율, 닉네임 호명 인식률, 게임 용어·밈·겹쳐 말하기에서의 오류 유형.

**확인 필요.** 설치할 정확한 버전, GPU 에서의 실제 속도, 한국어 방송 말투에서의 정확도.

**나중에 다시 볼 조건.** 닉네임 호명 인식이 너무 낮거나, 처리 시간이 방송 길이보다 길면 다른 모델이나 방식을 검토한다.

## D-05. 가상 채팅

**결정.** 가상(모의) 채팅은 **앱 화면 안에서만** 쓴다. 실제 치지직 채팅창이나 다른 어디로도 보내지 않는다.

**데이터 규칙.**
- 생성한 채팅은 실제 채팅 파일(`messages.jsonl`)과 섞지 않고 별도 시나리오 파일에 둔다.
- 각 채팅에 출처를 적는다: `replay`(실제 채팅 재생) · `retrieved`(같은 채널 다른 구간에서 가져옴) · `generated`(AI 가 만듦).
- 화면에서도 생성 채팅에 표시를 붙인다.
- 훈련 기록은 라벨 기록과 다른 종류·다른 파일로 둔다. 정답지에 섞이지 않게 하기 위해서다.

**첫 버전.** 스트리머 훈련(F)은 실제 채팅 재생만으로 시작한다. AI 생성은 H 단계에서 넣는다.

**문서 정리 필요.** README 의 "가짜 채팅을 만들거나 방송에 넣지 않습니다" 를 "훈련용 모의 채팅은 앱 안에서만 쓰고 어디에도 보내지 않습니다" 로 바꾼다. 07 질문 9(봇 계정 전송 vs 오버레이)는 이 결정으로 닫는다.

## D-06. 외부 AI 서비스

**결정.** 외부 AI(클라우드 LLM·클라우드 STT)는 쓸 수 있되 **최소 노출**만 허용한다.

| 규칙 | 내용 |
|---|---|
| 1. 기본 꺼짐 | 사용자가 켜기 전에는 아무것도 밖으로 나가지 않는다. 켤 때 무엇이 나가는지 화면에 보여 준다 |
| 2. 닉네임 제외 | 원 닉네임은 절대 보내지 않는다. 가명이나 "시청자1" 로 바꾼다 |
| 3. 필요한 조각만 | 방송 전체가 아니라 판정에 필요한 앞뒤 1~2분의 문장만 보낸다 |
| 4. 음성 안 보냄 | STT 는 로컬(D-04). 외부로는 글자로 바꾼 문장만 간다 |
| 5. 기록 | 언제 어떤 서비스로 몇 글자를 보냈는지 내 PC 에 남긴다 |
| 6. 로컬 먼저 | 같은 일을 로컬 LLM(이 PC 의 Ollama·LM Studio)으로 할 수 있으면 로컬을 기본으로 한다 |

**배치.** 외부 호출은 앱 본체가 아니라 엔진 도구에서만 한다. 앱이 접속하는 곳은 지금처럼 GitHub(업데이트)와 치지직(채팅 수집)뿐이다.

**확인 필요.** 채팅 문장을 외부 서비스로 보내는 것이 개인정보 처리위탁·국외 이전에 해당하는지 (05 11-3).

## D-07. 주제·유형 태그

**배경.** 반응한 채팅에 주제 태그(2~4단어)와 유형 태그(질문·공감·경험담·드립·정보)를 붙이면 주제 분석과 스트리머 프로필의 정답이 된다. 사람이 전부 달면 정확하지만 지친다. 이 제품의 목적은 사람이 하던 일을 AI 로 옮기는 것이다.

**검토한 방식**

| 방식 | 장점 | 단점 |
|---|---|---|
| ① 사람이 원할 때만 입력 | 부담이 적다 | 빠진 것이 섞여 통계가 흔들린다 |
| ② 사람이 반드시 입력 | 데이터가 빠짐없다 | 라벨러가 지친다 |
| ③ 따로 한 번 더 돈다 | 반응 판정에 집중할 수 있다 | 같은 장면을 두 번 봐 시간이 가장 길다 |
| **④ AI 가 먼저, 사람은 검토** | **가장 빠르다. 제품 목적과 맞다** | **AI 를 보면 사람이 쏠려 AI 가 실제보다 좋아 보인다** |

**결정.** ④를 쓴다. 쏠림은 아래 규칙으로 막는다.

| 규칙 | 내용 |
|---|---|
| 가린 표본 | 무작위로 고른 약 10% 는 사람이 AI 태그를 **보지 않고 먼저** 단다. 표본은 기존 무작위 추출(sha256-tau-v1)로 뽑아 사람이 고르지 않는다 |
| 정확도는 가린 표본으로만 | AI 태그 정확도는 이 10% 와의 일치로만 잰다. 검토로 확인한 90% 는 정확도 계산에 넣지 않는다 |
| 빠른 검토 | 나머지 90% 는 AI 태그를 보고 Enter 로 확인하거나 고친다 |
| 점점 줄이기 | 가린 표본에서 AI 일치도가 기준을 넘으면 검토를 표본 검사로 줄인다. 기준값은 시범 뒤 정한다 |
| 로컬 LLM | 태그 달기는 로컬 LLM 을 기본으로 한다 (D-06 규칙 6) |
| 기록 | 사람이 고쳤는지, 그대로 받았는지를 태그마다 남긴다 |

**반응 등급과의 구분.** "스트리머가 이 채팅에 반응했나" 의 등급은 엔진을 채점하는 기준이라 지금처럼 **사람이 AI 결과를 보지 않고** 매긴다 (안내서 원칙 3). 태그만 ④ 방식이다.

**문서 정리 필요.** 안내서 v0.2 초안에 "주제·유형 태그는 AI 제안 + 검토, 10% 가린 표본" 절을 더한다. 03 데이터 모델에 태그 필드(값, 출처 ai/human, 검토 여부, 가린 표본 여부)를 더한다.
