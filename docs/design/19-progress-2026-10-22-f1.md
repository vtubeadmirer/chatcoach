### 3-2. 출처 판정 멈춤 `adj_origin` (18 5-2 의 4번) — **한 번은 원인 확인, 다시 남음**

|---|---|---|---|
| 버그 담당 시험 | `adj_origin` | 스레드 10/10 이 `Suspended`. Acronis 로그에 그 프로세스를 '정지했다' 는 줄 1건 | **외부 정지 (Acronis Active Protection)**. 코드 교착 아님 |
| 통합, 실제 창 첫 실행 | `adj_open_a` | 스레드 15/15 `Suspended`, CPU 변화 0, 20분 넘게 풀리지 않음 | **외부 정지**로 본다. 둘째 실행은 75/75 |
| 검토 수정 뒤 | `adj_origin` 5번 중 4번 | 'Not Responding', faulthandler 덤프 없음. **스레드 상태는 보지 않았다** | **원인 미확인**. 외부 정지와 같은 모습이지만 확인하지 못했다 |

- Acronis 는 파일 만들기·지우기·바꿔치기(설정 저장의 임시 파일 → 바꿔치기 등)가 몰린 python.exe 를 랜섬웨어로 의심해 통째로 멈춘다.
  멈추면 감시 스레드도 같이 멈춰서 faulthandler 로는 스택을 못 찍는다.
- `player.py`·`origin_view` 의 재생기 조작에는 교착 경로가 없었다. 재생기를 다시 열거나 반복을 거듭 거는 일도 없다(새 시험으로 확인).
- gui_smoke 에 외부 정지 감시(`external_suspend=초`)를 넣었다. 다만 **정지가 풀린 뒤에만** 적힌다. 끝까지 안 풀리면 아무것도 못 적는다.
- Claude 는 정지된 프로세스를 한 번 다시 움직였다(NtResumeProcess, 버그 담당). 보안 프로그램의 판정을 거스른 것이라 앞으로 하지 않는다.
  통합 때는 다시 움직이지 않고 끝냈다(Stop-Process).

## 6. 사용자가 해 볼 것 (`<P>` 로, 클릭 순서만)

**먼저**: 시범 라벨링을 저장하고 그 프로젝트를 닫은 뒤에 한다(시범 프로젝트에서는 훈련 메뉴가 꺼져 있다).
`<P>` 에서 훈련을 열면 그 뒤 `<P>` 의 라벨링 세션은 노출로 세어 대표값에서 빠진다. `<P>` 는 개발용이라 괜찮다.

| 순서 | 누르는 것 | 볼 것 |
|---|---|---|
| 1 | 파일 → 최근 프로젝트 → `p15767532` | 세션 화면 |
| 2 | '보기 전용' | 작업대 |
| 3 | 메뉴 '훈련' → '스트리머 훈련' | 소리 끈 영상이 바로 재생, 채팅이 흐름, '고른 수 0' |
| 4 | (Space) | 멈춤·재생 |
| 5 | 읽고 싶은 채팅을 하나씩 누름 (몇 개) | '✓ 고름', 고른 수가 늚. 한 번 더 누르면 취소 |
| 6 | '견주기' (또는 Ctrl+Enter) | 같음·나만·원래만 표와 숫자 줄 |
| 7 | '원래만' 행 하나를 누름 | 소리가 켜지고 원래 대답 앞뒤가 재생된 뒤 멈춤 |
| 8 | (N, Shift+N) | 다음·앞 '원래만' 으로 |
| 9 | '닫기' | 작업대로 돌아감 |

클릭은 5번의 고른 수를 빼고 약 7번이다. 앱이 '응답 없음' 으로 굳으면 Acronis 알림을 확인하고 '복원' 은 누르지 않는다(5-2 의 1번).
