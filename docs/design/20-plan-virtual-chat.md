상태: **계획만 (D-18 9).** 코드는 아직 없다. 이 문서대로 다음 묶음에서 만든다.

## 2. 출처 세 가지

| 출처 | 무엇 | 어디서 오나 | 본문을 시나리오에 적나 | 연습 화면 표시 | 견주기 점수 |
|---|---|---|---|---|---|
| `replay` | 그 시각의 실제 채팅 그대로 | 같은 프로젝트 `messages.jsonl` | **아니오**(chat_id 만) | 없음 | **있음** — 원래 반응과 견준다 (F 와 같음) |
| `retrieved` | 다른 시각의 실제 채팅을 옮겨 놓은 것 | (가) 같은 방송의 **훈련 구간 밖** (나) 같은 `channel_id` 의 다른 프로젝트 | **아니오**(원 프로젝트·chat_id 만) | '가져옴' | 없음 — 원래 반응은 다른 맥락이라 정답이 아니다 |
| `generated` | 로컬 LLM 이 만든 채팅 | 엔진 도구 | **예**(만든 글자만) | '생성' | 없음 — 원래 반응이 있을 수 없다 |

- `replay`·`retrieved` 는 본문을 복사하지 않는다. 앱이 원 `messages.jsonl` 에서 읽어 화면에만 보인다. 원 채팅이 지워지면 그 줄은 '없음' 으로 건너뛴다.
- `retrieved` 의 이름 표시는 원래 채팅의 가림 닉네임(`nickname_masked`)이 아니라 **시나리오가 정한 가림 이름**을 쓴다. 다른 맥락에 실제 시청자 이름을 붙이지 않기 위해서다(8장 2번).
- `generated` 도 같은 모양의 가림 이름을 쓴다. 이름 모양으로 진짜·가짜가 드러나지 않게 한다(7장).

## 3. 시나리오 파일 형식 (H-1)

### 3-1. 자리와 규칙

| 항목 | 값 |
|---|---|
| 위치 | 프로젝트 `scenarios\SC-<yyyymmdd>-<4자>.jsonl`. 4자는 줄 목록 해시 앞 4자 |
| 스키마 | `schemas/scenario.schema.json` 새로 (`chatcoach-scenario-v1`) |
| 불변 | 한 번 쓰면 고치지 않는다. 다시 만들면 새 ID. 같은 해시면 새로 만들지 않는다(origin 대상 파일과 같은 방식) |
| 보호 구역 | `scenarios/` 를 `project.json` 의 `protected_zone` 기본값에 더한다. 내보내기·패키지에 넣지 않는다 |
| 쓰는 곳 | 엔진 도구만. 앱은 읽기만(훈련 세션) |
| 첫 줄 | `scenario.header` 1줄 |
| 나머지 | `scenario.chat` 줄, 보일 시각 순 |
| 마지막 줄 | `scenario.end` 1줄(건수·해시). 없으면 쓰다 끊긴 파일로 보고 열지 않는다 |

### 3-2. `scenario.header`

| 칸 | 뜻 |
|---|---|
| `schema` | `chatcoach-scenario-v1` |
| `scenario_id` | `SC-20261023-a1b2` 모양 |
| `project_id` | 이 시나리오가 붙는 프로젝트 |
| `range` | `vod_from_ms`·`vod_to_ms` (훈련 구간) |
| `created_at`, `created_by` | 시각, 도구 이름·판(`engine scenario 0.1.0`) |
| `inputs` | `messages_sha256`, `asr_sha256`(있으면), `topic_flow_sha256`(있으면), 다른 프로젝트에서 가져왔으면 그 `project_id`·`messages_sha256` 목록 |
| `fill` | 채우기 규칙 시작값: `quiet_window_ms`(60000), `quiet_max_real`(2), `target_per_min`(6), `max_virtual_ratio`(0.5) |
| `retrieval` | `method`(`topic_words`·`topic_words+e5`), 점수 하한, 같은 원 시청자 최대 횟수 |
| `generator` | `backend`(`none`·`lmstudio`·`external`), `model_id`, `model_sha256`(알 수 있으면), `prompt_template_id`·`prompt_sha256`, `temperature`, `seed`, `context_ms`(앞 몇 초를 넣었나) |
| `filters` | 거르기 판(`nickname-v1`·`copy-v1`·`block-v1`·`llm-check-v1`)과 걸러 낸 수 |
| `external` | `enabled`(기본 false). true 면 `log_ref`(보낸 기록 파일) |
| `counts` | 출처별 줄 수 |

### 3-3. `scenario.chat`

| 칸 | replay | retrieved | generated |
|---|---|---|---|
| `line_id` (`s0001` …) | ● | ● | ● |
| `source` | `replay` | `retrieved` | `generated` |
| `show_vod_ms` (보일 영상 시각) | ● | ● | ● |
| `chat_id` | ● | — | — |
| `from_project_id`, `from_chat_id`, `from_t_ms` | — | ● | — |
| `from_scope` | — | `same_broadcast` · `same_channel` | — |
| `retrieval_score` | — | ● | — |
| `gen_id`, `text` (최대 100자) | — | — | ● |
| `context` (`asr_from_ms`·`asr_to_ms`·`topic_id`) | — | — | ● |
| `display_mask` (가림 이름, 예 `하**`) | — | ● | ● |
| `emotes` (합성 코드만 허용 목록) | — | — | ● |
| `checks` (`nickname_hit`·`copy_max`·`blocked`·`llm_flag`) | — | ● | ● |

- `replay` 줄은 "이 구간의 실제 채팅을 다 보인다" 는 뜻으로 **적지 않아도 된다.** 앱이 구간의 실제 채팅을 읽고 시나리오 줄을 끼운다. 다만 실제 채팅을 일부만 보일 때(예: 너무 많은 구간 줄이기)는 `replay` 줄로 적는다. 첫 판은 '다 보임' 하나만 한다.
- 06 4-7·03 5-6 의 `generation_ref` 는 `{file: "scenarios/SC-….jsonl", gen_id}` 로 이 파일을 가리킨다.

## 4. 만드는 방법 후보 (로컬 먼저)

### 4-1. 순서

| 순서 | 방법 | 필요한 것 | 잘하는 것 | 모자란 것 | 못 쓸 때 |
|---|---|---|---|---|---|
| ① | **retrieved** — 실제 채팅에서 고르기 | 그 프로젝트(또는 같은 채널 프로젝트)의 `messages.jsonl`, 주제 흐름 낱말(있으면), e5-small(있으면) | 말투가 진짜다. AI 가 필요 없다. 빠르다 | 그 순간 말에 딱 맞는 채팅이 드물다. 같은 시청자 말버릇이 반복될 수 있다 | 가져올 채팅이 모자라면 있는 만큼만 넣고 `counts` 에 적는다 |
| ② | **generated (로컬 LLM)** — LM Studio | LM Studio **서버가 켜져 있어야** 한다(`http://localhost:1234`), 이미 있는 LLM 2개 가운데 하나 | 그 순간 스트리머 말에 맞춘 채팅을 만든다 | 말투가 어색할 수 있다. 한국어 채팅 말투·밈을 모를 수 있다. 느리다 | 서버가 꺼져 있으면 **생성 0건으로 멈추고** `lmstudio_off` 를 낸다. 외부로 넘어가지 않는다. retrieved 만으로 시나리오를 만들지는 `--generate off` 를 적을 때만 |
| ③ | **generated (외부 AI)** | 사용자가 켬, D-06 6규칙, 05 11-3 확인(처리위탁·국외 이전) | 말투 품질이 나을 수 있다 | 개인정보·비용·약관 | **기본 꺼짐.** 이번 H 범위에서는 만들지 않는다(8장 위험, 11장 5번) |

### 4-2. ① retrieved 고르는 법

1. 훈련 구간을 1분 창으로 나눈다. 창마다 실제 일반 채팅(`kind = text`) 수를 센다.
2. 실제 채팅이 `quiet_max_real` 이하인 창이 **채울 자리**다(5-1).
3. 채울 자리의 '그때 주제' 를 정한다: 주제 흐름의 낱말(있으면) + 그 앞 60초 전사문의 낱말.
4. 후보 채팅: (가) 같은 방송에서 **훈련 구간 밖** (나) `project.json` 의 `channel_id` 가 같은 다른 프로젝트. **`pilot-*` 는 잠기기 전 후보에서 뺀다.**
5. 뺄 것: 일반 채팅이 아닌 것(후원·구독·공지 등), 다른 시청자 닉네임이 든 것, 금칙어(8장), 너무 짧은 것(이모티콘만·한 글자).
6. 점수 = 주제 낱말 겹침(+ e5-small 유사도가 있으면 섞음). 하한 넘는 것 가운데 위에서 고른다. 같은 원 시청자는 시나리오 하나에 최대 3번.
7. 보일 시각은 창 안에서 고르게 흩는다(seed 고정, 다시 돌려도 같다).

### 4-3. ② 로컬 LLM 으로 만드는 법

| 항목 | 값 |
|---|---|
| 부르는 곳 | 엔진 도구(엔진 venv). OpenAI 호환 `POST /v1/chat/completions`, localhost 만 |
| 서버 확인 | 먼저 `GET /v1/models`. 응답이 없으면 `lmstudio_off` 로 멈춤. 모델을 내려받거나 서버를 대신 켜지 않는다(첫 판) |
| 모델 고르기 | 설정 파일에 적은 `model_id` 하나. 없으면 멈춤(`model_missing`). 고르는 창 없음 |
| 넣는 것 | 그 자리 앞 60~120초 **전사문**, 주제 낱말, (선택) 앞 30초 실제 채팅 몇 줄의 **본문만**. 닉네임·가림 이름·chat_id 는 넣지 않는다 |
| 지시문 | 고정 판(`prompt_template_id`). "시청자 채팅 n개, 한 줄에 하나, 30자 안팎, 실제 사람·다른 시청자를 부르지 말 것, 후원·운영자 말투 금지" |
| 나오는 것 | 줄마다 글자만. 이름·시각은 엔진이 붙인다 |
| 다시 재현 | `seed`·`temperature` 고정. 그래도 LLM 이 같은 답을 낸다는 보장은 없어 **만든 글자를 시나리오에 저장**한다 |
| 거르기 | 8장 1~4번을 통과한 줄만 넣는다. 걸러 낸 수만 `filters` 에 |
| 전사문·채팅이 LLM 에 주는 지시 | 지시로 듣지 않게 지시문을 나눈다. 나오는 것은 글자뿐이고 도구 호출·파일 쓰기가 없어 피해가 작다 |

### 4-4. ③ 외부 AI (만들지 않음, 켜는 조건만)

로컬 생성이 7장 품질 관문을 두 번 못 넘고, 사용자가 켜기로 하고, 05 11-3 확인이 끝났을 때만 다시 정한다. 그때도 D-06 1~5(무엇이 나가는지 보임·닉네임 없음·앞뒤 1~2분 문장만·음성 없음·보낸 기록)를 지킨다.

## 5. F 스트리머 훈련에 붙이는 법 (H-4)

### 5-1. '채팅이 없을 때' 의 뜻

| 경우 | 하는 일 |
|---|---|
| 구간 안에 채팅이 드문 1분 창이 있다 | 그 창만 채운다(`target_per_min` 까지, 실제+가상 합). 채팅이 많은 곳은 건드리지 않는다 |
| 구간 전체가 드물다(작은 방송) | 전체를 채우되 가상 비율은 `max_virtual_ratio`(0.5) 이하 |
| 실제 채팅이 하나도 없다 | 첫 판은 하지 않는다(견줄 replay 가 없다). 11장 3번 |

### 5-2. 화면과 흐름

| 동작 | 결과 | 클릭 |
|---|---|---|
| 메뉴 '훈련 → 스트리머 훈련 (가상 채팅 섞기)' | F 와 같은 훈련 화면. 이 구간의 **가장 새 시나리오**를 자동으로 쓴다. 고르는 창 없음 | 1 |
| 시나리오가 없거나 깨짐 | 메뉴가 꺼지고 까닭 한 줄('가상 채팅이 아직 없습니다') | 0 |
| 시범 프로젝트(잠기기 전) | 메뉴가 꺼짐(F 와 같은 까닭 줄) | 0 |
| 채팅 한 번 누름 / 다시 누름 | F 와 같음: 고르기 / 취소. 가상 채팅도 고를 수 있다 | 1 |
| 채팅 패널 | 실제 채팅과 시나리오 줄을 시각 순으로 섞어 흘린다. `retrieved` 에 '가져옴', `generated` 에 '생성' 작은 표시 | 0 |
| 견주기 | F 의 표(같음·나만·원래만)는 **replay 만으로** 낸다. 아래에 한 줄: '가상 채팅 m개 가운데 k개 고름'. 가상 채팅 행은 '연습용, 점수 없음' 묶음 | 0 |

- 숫자 줄(맞힌 비율·시각 차)은 replay 만 센다. 가상 채팅이 F 점수를 바꾸지 않는다.
- 소리 끄기·N/Shift+N·행 누르면 소리 켜고 듣기는 F 그대로. 가상 채팅 행을 누르면 그 시각으로 가지만 '원래 대답' 은 없다.
- 기준(최종 세트·손라벨 CSV)이 없는 구간: 첫 판은 F 와 같이 메뉴를 끈다. 11장 4번.

### 5-3. 훈련 기록 (F 의 training-event 에 더할 칸)

F 담당이 만드는 `schemas/training-event.schema.json` 에 **선택 칸만** 더한다(label-event 는 그대로).

| 줄 | 더할 칸 |
|---|---|
| `training.start` | `scenario_id`, `scenario_sha256` (없으면 생략 = 지금의 F) |
| `training.pick` / `unpick` | `source` 가 `replay`·`retrieved`·`generated`. 가상이면 `chat_id` 대신 `line_id` |
| `training.compare` | `virtual_shown`, `virtual_picked` (건수만) |
| `training.judge` (새, 7장) | `line_id` 또는 `chat_id`, `answer`(`real`·`virtual`·`unsure`), `judged_vod_ms` |

- 노출: 가상 채팅 훈련 세션도 F 처럼 **노출로 센다**(18 6-5 3번). 시나리오에 원래 반응은 없지만 replay 견주기가 정답을 보인다.

## 6. 시청자 훈련(G)과의 관계

| 주제 | 정한 것 (제안) |
|---|---|
| 같이 쓰는 것 | 시나리오 파일 형식, 거르기(8장), 가림 이름, `training-event` 의 source 칸 |

## 7. 평가 — 사람이 진짜·가짜를 가려내는 비율 (H-5)

18 6-4 H-5 의 '그럴듯함 / 어색함 / 모르겠음' 을 **'진짜 / 가짜 / 모르겠음' 가려내기**로 바꾼다(9장 설계와 다르게 한 곳 1번). 가려내지 못할수록 그럴듯하다는 뜻이라 한 번에 둘 다 잰다.

### 7-1. 흐름

| 동작 | 결과 | 클릭 |
|---|---|---|
| 메뉴 '훈련 → 가상 채팅 가려내기' | 시나리오 구간을 소리 켜고 튼다. 이 화면에서만 '가져옴·생성' 표시를 **숨긴다**. 맨 위에 한 줄 '이 화면에는 생성 채팅이 섞여 있습니다' | 1 |
| 채팅 옆 단추 '진짜' · '가짜' · '모르겠음' | 그 채팅의 판정. 다시 누르면 바꿈 | 채팅마다 1 |
| 구간 끝 | 판정한 채팅마다 정답 표시가 붙고 숫자 줄이 나온다 | 0 |

- 대상은 사람이 고르지 않는다: 구간에 보인 채팅 **전부**(실제 + 시나리오 줄).
- 판정하지 않은 채팅은 '안 봄' 으로 세고 혼동표에 넣지 않는다.
- 같은 사람이 같은 시나리오를 두 번 가려내면 두 번째는 '다시 봄' 으로 표시하고 대표값에서 뺀다.

### 7-2. 계산 (06 4-7 재사용)

| 항목 | 값 |
|---|---|
| A 쪽(정답) | 시나리오에서 만든다: `replay`·`retrieved` → `real`, `generated` → `virtual`. method = `generation_log_match` |
| B 쪽(사람) | `training.judge`: 진짜 → `real`, 가짜 → `virtual`, 모르겠음 → `undeterminable`. method = `manual` |
| 짝 키 | replay 는 `chat_id`, 시나리오 줄은 `scenario_id:line_id` |
| 계산 | `app.core.origin.compare_origins(a, b, strict=False)` 하나. 3×3 혼동표·명목 κ |
| 주의 | A 쪽이 모두 '자동' 이라 결과의 `human` 묶음은 비고 `all` 만 뜻이 있다. 보고에 1줄 적는다 |
| 더 내는 숫자 | 가짜 탐지율(생성 → 가짜라고 맞힘 / 생성 판정 수), 진짜 오인율(실제 → 가짜라고 함 / 실제 판정 수), '모르겠음' 비율. `retrieved` 는 따로 한 줄(실제 채팅인데 옮겨 놓은 것이라 어색해 보이는지) |

### 7-3. 관문 (시작값, 시범 뒤 고친다)

| 관문 | 시작값 | 뜻 |
|---|---|---|
| 표본 | 생성 40줄 이상 + 실제 40줄 이상, 방송 2편 이상 | 적으면 숫자를 내되 '표본 적음' |
| 통과 | 가짜 탐지율 **0.65 이하** 이고 κ **0.4 이하** | 사람이 가짜를 잘 못 가린다 = 연습에 섞어도 크게 튀지 않는다 |
| 실패 | 위를 넘으면 지시문·모델·거르기를 바꿔 새 시나리오로 다시 잰다. 두 번 실패하면 4-4(외부 AI) 여부를 사용자에게 묻는다 | |

- 가려내는 사람이 그 방송을 최근에 봤으면 실제 채팅을 기억해 탐지율이 올라간다. 보고 머리에 '이 구간을 본 적 있음' 여부(세션 기록으로 계산)를 적는다.
- 평가용 구간은 `<P>`(`p15767532`) 사본이나 합성 프로젝트. 시범 프로젝트는 잠기기 전 쓰지 않는다.

| 2 | LM Studio 서버를 누가 켜나 | 첫 판은 사용자가 LM Studio 에서 서버를 켠다(2번 누름: 개발자 탭 → 서버 시작). `lms` 명령이 있으면 엔진 도구가 `lms server start` 를 부를 수 있는지 H-3 처음에 확인하고, 되면 0번 |
| 3 | 실제 채팅이 하나도 없는 영상(예: 혼자 녹화한 연습 영상) | 첫 판은 하지 않는다. replay 가 없으면 견줄 것이 없다. 수요가 있으면 H 뒤 '전부 가상' 모드를 따로 정한다 |
| 4 | 기준(최종 세트·손라벨 CSV)이 없는 구간에서 가상 채팅 연습 | 첫 판은 F 처럼 끈다(D-18 7 과 같은 관문). 작은 방송 연습이 필요하면 '점수 없이 고른 수만' 을 다음 판에서 연다 |
| 5 | 외부 AI 를 H 에 넣나 | 넣지 않는다. 7-3 관문을 두 번 실패하고 05 11-3 확인이 끝난 뒤 사용자에게 묻는다 |
| 6 | 금칙어 목록을 어디 두나 | 저장소 밖 `chatcoach-data\config\blocklist-ko.txt`, 엔진이 해시를 시나리오 `filters` 에 적는다. 시험은 합성 낱말 목록으로 한다 |
| 7 | LLM 입력에 실제 채팅 본문을 넣나(9장 4번) | 기본 끔. 7-3 관문을 못 넘으면 켜서 견준다(로컬, 닉네임 빼고) |
| 8 | 어느 LLM 을 쓰나 | 이미 있는 2개 가운데 한국어가 나은 쪽 하나를 H-3 처음에 합성 문장 10개로 보고 설정에 고정. 새로 받지 않는다(18 6-5 6번) |
| 9 | 시나리오를 앱 단추로 만들게 하나 | 첫 판은 엔진 도구만(Claude 가 돌림, 사용자 0번). 사용자가 직접 만들고 싶어 하면 '훈련 → 가상 채팅 만들기' 메뉴 1번이 엔진 도구를 부르게 한다(H 뒤) |
| 10 | `retrieved` 도 가림 이름을 새로 붙이나 | 붙인다(8장 3번). 원 가림 닉네임을 쓰면 가려내기에서 바로 드러나고, 다른 맥락에 실제 이름을 붙이게 된다 |
| 11 | training-event 스키마에 선택 칸을 더하는 때 | F 첫 묶음이 스키마를 만든 뒤 H-4 에서 선택 칸만 더한다. F 의 옛 기록은 그대로 읽힌다 |
